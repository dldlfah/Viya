### 2.1. 레벨업 선택 규칙 — 프로듀서 확정 범위

2026-11-17 추가 지시:

> 레벨 선택에선, 기본 3가지 선택지를 랜덤으로 주고, 모든 클래스 공통 스킬 8가지, 비야 전용 스킬 1, 패시브 8가지(저항력 제외), 비야 전용 필살기 강화스킬 1(각 캐릭마다 게임할 때 변경되게끔) 이렇게 일단 가자.

기존 두 줄 UI 문맥에 따라 공통 스킬과 캐릭터 전용 스킬은 공격 스킬 계열로 분류한다. 아래 수량은 **한 캐릭터로 출격할 때 구성되는 레벨업 후보 종류 수**다.

| 분류 | 종류 수 | 적용 범위 |
| --- | ---: | --- |
| 모든 클래스 공통 공격 스킬 | 8 | 클래스/주력 캐릭터와 무관하게 공유하는 후보 |
| 주력 캐릭터 전용 스킬 | 1 | 비야 출격 시 비야 전용 스킬. 다른 캐릭터 전용 스킬은 섞지 않음 |
| 공통 패시브 스킬 | 8 | **저항력 계열 제외**. 속성 저항/모든 저항을 이 후보군에 넣지 않음 |
| 주력 캐릭터 고유 필살기 강화 스킬 | 1 | 비야 출격 시 비야의 고유 마법 강화. 주력 캐릭터 변경 시 해당 캐릭터의 강화 스킬로 교체 |

- 레벨업마다 **기본 3개 후보를 무작위 제시하고 1개 선택**한다.
- 비야 전용 스킬과 비야 필살기 강화는 다른 항목이다. 필살기 강화는 새 필살기를 추가하는 것이 아니라 해당 캐릭터의 기존 고유 액티브 마법을 강화한다.
- 원화/수집/새 캐릭터 제작을 시작하지 않는다. 캐릭터별 전용 후보 교체는 데이터 연결 구조를 먼저 만들며, 이번 실제 캐릭터는 비야만 유지한다.
- 패시브에서 저항을 제외한 것은 이후 서포터 저항 버프의 폐기를 뜻하지 않는다. 서포터 버프 자체는 계속 보류한다.
- **스킬의 이름·구체 효과·수치·최대 강화 레벨·출현 가중치는 아직 미확정이다.** 이번 지시를 근거로 18개 스킬 내용을 임의 확정하지 않는다. 구현에 필요한 시제품 값은 임시로 표시한다.

### 2.2. GAME-002 구현 시 적용할 기본 처리

아래는 위 기획을 연결하기 위한 구현 기준이며, 미확정 콘텐츠나 수치를 새로 승인하는 조항이 아니다.

- 주력 캐릭터 ID로 전용 스킬 ID와 고유 필살기 강화 ID를 가져온다. 비야를 선택창 코드에 고정하지 않고, 재시작/다른 캐릭터 출격 시 이전 캐릭터의 후보와 강화 상태가 남지 않게 한다.
- 공격/패시브 보유 상태는 기존 두 줄 HUD와 연결한다. **필살기 강화 상태는 별도 고유 마법 영역에서 관리하는 구현안**을 기본으로 하되, 일반 공격/패시브 슬롯 점유 여부는 최종 장착 규칙 확정과 구분한다.

- 캐릭터별 후보 구성, 3개 중복 없는 추첨, 저항 제외, 적용/재시작 초기화에 대한 검사와 실제 게임 화면 연결을 각각 검증한다. 기획 기록만으로 선택 시스템 구현 완료를 주장하지 않는다.

#### 후속 철수 보상 검토안

현재 철수 보상은 활성화하지 않았다. 기존 전투 포기0금화와 정상 클리어의 전체 획득+기본 보상을 유지한다. 아래20%는 경제 비교를 위한 **미확정 임시 제안**이다.

- 120초/240초 체크포인트 도달 후 명시적 확인으로 철수한다. 전화/백그라운드/저장 후 중단은 이어하기로 처리하고 철수로 자동 변환하지 않는다.
- 비교안은 **바닥 금화와 기본 보상을 제외한 획득 금화의20%를 내림 지급**한다. 다음 스테이지를 열지 않는다. 클리어 기본100과 달리 철수 기본 보상은0으로 가정한다.
- 현재 확률30%에서 일반 드롭의 기대값은30×0.3=9금화/처치, 정예/보스는550×0.3=165다. 예시75처치의2분 구간은 일반74+정예1로 기대831,20% 지급166금화다.4분174처치는 일반172+정예2로 기대1878,20% 지급375금화다.6분292처치 클리어는 일반289+정예2+보스1+기본100으로 기대3196금화다. 이는 모든 드롭을 획득했다고 가정한 계산이며 실제 지급 결과나 최종 경제 합격이 아니다.

| 비교 예시 | 지급 제안 | 시간당 효율 |
| --- | --- | --- |
| 2분 철수 | 166금화/120초 | 약83금화/분 |
| 4분 철수 | 375금화/240초 | 약94금화/분 |
| 6분 정상 클리어 | 기대3196금화/360초 | 약533금화/분 |

이 비교에서 철수 효율은 정상 클리어의 약16~18%다. 실제 시제품은 수집 동선·휴식·재출격 시간·난수 분포와 향후 스테이지 차이를 포함해 재측정한다. 낮은 난도 정예만 반복하는 행위와 고정 보상/시간을 늘리는 조정도 함께 검토한다.

**지급 원장이 선행되어야 한다.** 현재 `last_run` 한 개와 스테이지 번호는 클리어처럼 번호가 증가할 때 이전 지급을 막는다. 철수로 같은 스테이지에서 반복 지급하면 더 오래된 철수 ID를 다시 제출하는 문제가 생긴다. 출격 세대나 정산 기록으로 모든 소모한 출격을 식별하고, 종료 의도 저장 → 정산 → 재실행 확인을 묶어야 한다. 이전 체크포인트 재사용·정산 중 종료·동일 ID 재시도·골드 파일 실패/호환을 시제품에서 검증한다. 이 선행 작업과 보상률은 현재 미구현/미확정이다.

#### 장시간 콘텐츠

- 15~20분 도전 전투는 기본 캠페인 완성 뒤 별도 규칙과 성장 곡선으로 검토한다.
- 무한 생존은 누적 난도·종료·저장 크기 상한을 별도 설계한다.
- 특별 보스/고난도 스테이지는 패턴과 목표 시간을 별도 검토한다.
- 현재 실제 모드는 기본6분 캠페인이다. 상점·금화 사용처·영구 성장과 장시간 모드는 기획 항목으로 유지한다.

### 2.8. 최신 지시 — 임시 메인 로비·계정 공통 골드 특성

GAME-012에서 기존 메인 로비와 공격/방어/회복 특성창을 연결했다. 방어와 회복은 실제 빈 내용 영역으로 유지한다. 공격만3단계를 순서대로 구매하며 단계별 비용은 사용자 지정1,000/50,000/1,000,000골드다. 누적 공격력+5/+10/+15%는 “임의로” 요청에 따른 임시 수치다. 계정 공유 비용/배율은 AccountTalents, 골드와 단계의 원자 저장은 기존 GoldProgress, 실제 새 전투의 공통 피해 배율은 기존 RunState를 사용한다.

이 지시는 이전 금화 사용처/영구 성장 보류 중 **계정 공격 특성3단계**를 대체한다. 기존 골드 파일에 schema1/공격 단계를 함께 저장하고 예전 계정은 잔액/해금/기지급 ID를 유지한0단계다. 실제 신규 계정은0골드이며 시험용 자금은 생산 경로에 넣지 않았다. 다른 캐릭터도 같은 출격 경로로 공통 적용되도록 연결하고 fixture로 검증했다. 현재 실제 캐릭터는 비야이며 온라인 계정/로그인·동기화는 이번 범위에 없다.

새 전투는 현재 계정 특성을 적용한다. 이어하기는 출격 당시 단계를 유지하며 저장 전투를 둔 채 로비에서 구매해도 전투 능력치를 소급 변경하지 않는다. 새 출격/확인 후 재시작부터 최신 단계를 적용한다. 저장4는 알려진 이전 저장1·2·3을 특성0으로 변환해 기존 전투를 보존한다. 종료 상태는 정산/복구를 마친 뒤 시작 로비로 돌아가며 실패 시 재시도 경로를 유지한다.

실제 UI 구매·부족/상한·중복/오래된 요청·실패/재시도·기존 지갑·클리어 정산·다른 캐릭터·전투 저장/재실행을 검증했다. 엔진2020 checks/Python12 tests와 일반/compact Linux 렌더는 PASS다. **모바일 실기, 특성별 완주율/성장/가격 대비 경제는 미검증**이다. GAME-011의14~17선택/이전10~12목표 초과는 과거 근거이며 이번 단위에서6분 측정을 새로 실행하지 않았다.

후속 검토는 지정 비용을 유지한 상태에서 강화 단계별 성장·정예/보스 처치·금화 공급을 비교한다. 현재 방어/회복 특성·추가 공격 특성·상점/환불/재분배는 만들지 않는다. 철수 보상률·원장 시제품,15~20분/무한/특별 보스는 기존 후속 기획이다. 다음 단일 게임 작업은 기존 실제 원거리·비행 접근의 모바일 표시이며 로비/특성창과의 입력·정지 관계를 함께 보존한다.

## 3. 보류 작업 — 비야 원화 제작 방식 (재개할 때 적용)

**현재는 실행하지 않는다.** 아래는 직전 논의의 통합 기록이며 도구 성능 보증이 아니다.

- 승인된 ART-001은 **디자인 기준**, 이미 생성된 정면/측면/후면은 **수정 대상 파생 원화**다. 둘을 구분한다.
- 원화 생성·수정은 **Higgsfield로 통일하는 방향**을 채택한다. 다만 플랫폼 이름이 아닌 모델·입력 참조·설정까지 기록한다. 임의로 다른 이미지 도구로 바꾸거나 전체를 재생성하지 않는다.
- 직전 조회에서 Nano Banana 2의 참조 이미지·마스크 입력 및 `is_inpaint`를 확인했다. **재개 시 가용 모델/파라미터/잔액/견적을 다시 조회**한다. 기능 제공과 캐릭터 일치도는 별개다.
- 첫 수정은 한 방향의 한 부위(예: 허벅지 스트랩)로 제한한다. 원본 이미지 + 해당 부위 마스크 + 승인 디자인을 전달하고, 얼굴/체형/소매/갑옷/색채 등 수정 대상 밖의 변경을 금지한다.
- 원본 보존을 프롬프트에만 맡기지 않는다. 편집 범위 밖을 원본으로 유지하는 합성·차이 검사를 적용한다. 실루엣/옷자락이 바뀌면 필요한 배경 여백도 마스크에 포함하고 경계가 자연스러운지 확인한다.
- 전후 이미지·마스크·모델·파라미터·작업 ID·비용·실제 검수 결과를 보존한다. 부분 편집 1건의 보존성이 확인된 뒤 범위를 확장한다.
- R1/R2는 기존 부분 수정이 아닌 **전체 재생성 실패/미승인 자료**다. 새 흰 소매/갑옷/장식/170cm·신체 치수는 기준에서 제외한다. SAM 3D 초안도 정식 모델로 사용하지 않는다.
- 모든 머리카락 가닥까지 원화 4장을 맞추는 무한 작업을 하지 않는다. 얼굴·체형·의상 구성·물리적 좌우 비대칭을 우선 정리하고, 후속 단일 3D 형상에서 각 시점을 대조한다.

## 4. 보류 작업 — 모델링·의상·애니메이션

원화 수정 재개 및 결과 검토 이후의 계획이다. 단일 신체·공통 골격·교체 가능한 의상 파츠를 지향하되 현재 메시가 존재하거나 코스튬 교체가 완성됐다고 간주하지 않는다. 기본 전투복 한 벌과 최소 동작부터 다룬다. 실시간 3D와 3D 기반 2D 스프라이트 중 최종 표현은 실제 품질/모바일 성능을 보고 결정한다. 새 3D 생성 비용/리깅은 별도 승인 조건을 따른다.

## 5. 운영·검증

같은 활성 작업 브랜치에 의미 단위로 보존하고 `main`에 자동 병합하지 않는다. 사용자에게 매회 Pull·로그를 요구하지 않는다. 문서/커밋/검사 개수를 진척률로 삼지 않는다. `코드 작성`, `기본 정적 검사`, `Godot 구문·타입 검사`, `엔진 동작`, `렌더`, `모바일 실기`, `아트 승인`을 구분한다. 실행하지 못한 것은 `NOT_VERIFIED`, 실제 결함은 `FAIL`로 기록한다. 유료 Actions·원화 자동 재생성·미승인 디자인 승격은 금지한다.

## 6. 캐릭터 수집·성급 성장·서브 콘텐츠 기획 (2026-11-18)

> **문서 상태:** 본 절은 별도의 기획 논의에서 확인된 사용자 의사결정을 기록한다. \`[확정: 방향]\`은 게임 설계 원칙이 합의되었다는 뜻이지 코드 구현 완료를 뜻하지 않는다. \`[잠정]\`은 수량·구성의 초안, \`[제안]\`은 검토할 설계안, \`[미확정]\`은 추가 의사결정이 필요한 항목이다. 기존 GAME-012 및 개발 세션의 NEXT_TASK 작업 지시를 변경하지 않는다. 본 절은 수집·가챠·서포터·서브 콘텐츠를 **즉시 구현하라는 지시가 아니다**.

### 6.1. 프로젝트 성격과 구분

- [확정: 방향] 모바일 가로형 **6분 서바이버 액션 전투**를 메인 플레이로 유지하면서, **캐릭터 수집·성급 육성·탐색·도시 방어**를 결합하는 중장기 방향을 논의한다. 마왕군에 맞서는 최후의 도시라는 기존 세계관과 연결한다.
- [기존 기획 확정] 메인 서바이버 전투는 주력 캐릭터 **1명 직접 조작**과 자동 공격, 수동 고유 마법으로 진행한다. 전투 안의 경험치/무작위 3선택 성장은 **전투별 초기화**되는 별도 체계다. 공격/패시브 2줄 및 공격 서포터 2칸·패시브 서포터 2칸의 현재 UI 기준을 보존한다.
- [구현 구분] 6분/2·4분 체크포인트·5분 보스 등의 실제 구현·검증 기록은 앞선 2.5~2.7절과 CURRENT_WORK/DEVELOPMENT_STATUS를 따른다. GAME-012의 계정 공통 공격 특성·금화 구매 기능은 이미 별개로 존재하므로, 여기서 논의하는 **캐릭터별 성급 강화/가루/뽑기**와 혼동하지 않는다.
- [미확정] 영구 성급이 전투 내 레벨업·주력 캐릭터의 기본 능력치·서포터 효율에 구체적으로 어떻게 영향을 주는지 수치와 규칙은 정하지 않았다.

### 6.2. 캐릭터 성급·5성·중복 처리

| 항목 | 상태 | 기준 |
| --- | --- | --- |
| 성급 계열 | [확정: 방향] | D → C → B → A → S → SS → SSS |
| 등급별 별 | [확정: 방향] | 각 등급에 **5개 별**을 두고, 해당 캐릭터 **전용 조각**으로 채운다. 비어 있는 별은 기본적으로 드러나지 않는 표현을 지향한다 |
| 등급 진화 | [확정: 방향] | 현재 등급의 **5성 달성**을 다음 등급 진화의 필수 전제로 삼는다. 예: 비야 D 5성 → C급 진화 가능 |
| 성장 상한 | [확정: 방향] | 캐릭터마다 도달할 수 있는 **최대 등급**이 정해져 있다. 상한에 도달한 캐릭터도 **그 등급의 5성**까지 성장 가능하나 다음 등급으로 진화하지 못한다 |
| 중복 뽑기 | [확정: 방향] | 이미 보유한 캐릭터의 중복 카드는 해당 캐릭터 **조각**으로 사용한다 |
| 성장 완료 후 중복 | [확정: 방향] | **최대 등급 5성**에 도달한 뒤 남는 중복 획득분은 **가루**로 전환하여 다른 캐릭터의 등급 진화 재료로 활용한다 |

| SSS 이후 | [미확정] | 앞서 언급된 '무한 성장'이 **SSS 5성 이후 추가 성장**을 뜻하는지 미정이다. 능력치 무제한 증가를 승인한 것은 아니다 |

- [확정] **비야**는 무료 기본 주력 캐릭터로 **현재 D급에서 시작**하고 **최대 SSS급**까지 성장한다. 세계관의 핵심 주인공이며 **물리 공격형 최상위**로 설정한다. 기존 소총·진홍 룬 마법 정체성을 유지한다.
- [확정: 방향] 비야 외에도 **SSS까지 성장 가능한 소수의 주인공급 캐릭터**가 존재한다. 다른 캐릭터는 각자 정해진 상한을 적용한다.
- [설계 해석/추후 검증] 비야가 D 0성에서 SSS 5성까지 모두 밟는다면 **별 강화 35회, 등급 진화 6회**다. 구체적으로 진화 직후 별 상태가 0성으로 바뀌는지, 별 진화 시 재료 추가 소모가 필요한지는 아직 수치·UX 확정이 아니다.
- [제안] 세계관 최상위 물리 공격자와 전투의 모든 상황에서 절대적 최고 성능이라는 의미를 구분한다. 다른 영웅은 특정 속성·방어·지원·탐색 등의 전문성을 유지할 수 있어야 한다. 능력의 실제 우열/시너지/최종 각성 효과는 미확정이다.

### 6.3. 캐릭터 인원 초안 — 최대 성장 가능 등급별

아래 숫자는 사용자가 **대략 제시한 후보 규모**이므로 확정 출시 명단이나 초기 구현량이 아니다. 특히 **비야는 현재 D급이지만 최대 SSS급 그룹으로 집계**하며, D급 50명은 최대 D급 캐릭터 후보를 뜻한다.

| 최대 등급 | 잠정 인원 | 주된 제작 범위(기획 방향) |
| --- | ---: | --- |
| SSS | **5** (비야 + 다른 주인공급 4) | 메인 전투 액션 + 지원/서브 콘텐츠 |
| SS | 6 | 메인 전투 액션 + 지원/서브 콘텐츠 |
| S | 8 | 메인 전투 액션 + 지원/서브 콘텐츠 |
| A | 15 | 메인 전투 액션 + 지원/서브 콘텐츠 |
| B | 20 | **주력 액션 제작 대상 제외**, 지원/서브 콘텐츠 |
| C | 30 | **주력 액션 제작 대상 제외**, 지원/서브 콘텐츠 |
| D | 50 | **주력 액션 제작 대상 제외**, 지원/서브 콘텐츠 |
| **합계** | **134명** | 상위 후보34명 / 하위 후보100명 |

- [확정: 방향] **A~SSS급 영웅군에만 메인 스토리 직접 조작 전투용 액션 시스템을 제작**한다. **B~D급은 전용 전투 액션을 만들지 않고** 캐릭터 일러스트·서포터·탐색·도시 방어 등 서브 콘텐츠에 활용한다.
- [논리상 필수 예외] 기본 D급 상태의 비야도 처음부터 메인 전투 주력으로 사용한다. **최대 성장 가능 등급을 기준으로 액션 대상 34명을 분류하는 방식**이 기존 구상과 가장 일관적이지만, 다른 성장형 영웅의 정확한 출전 자격 판정 규칙은 **추후 명문화**한다.
- [미확정] 위 인원 배분의 최종 규모, 최초 출시 인원, 개별 캐릭터 명단/배경/직업, 신규 캐릭터 추가 속도, 같은 인물의 변형 캐릭터를 별개로 셀지는 정하지 않았다.
- [제안] 상위 캐릭터는 개별 모델·이동/사격/피격·고유 액티브 등을 제작하되, 하위 100명은 **고유 초상화/설정/능력 데이터 중심**으로 구현한다. 도시 방어 장면에는 직업/부대별 공통 모델을 재활용해 제작 규모를 통제한다.
- [주의] **저등급 캐릭터의 수가 많다고 상위 등급 뽑기 확률이 자동으로 낮아지지 않는다.** 등급별 확률, 개별 캐릭터 확률, 천장, 픽업, 중복 조각 분산은 별도로 설계해야 한다.

### 6.4. 잉여·하위 등급 캐릭터의 활용 영역

- [기획 방향/세부 미확정] **탐색·원정:** 폐허 도시·광산·마왕군 점령지·고대 유적 등으로 여러 캐릭터를 편성하는 기능을 검토한다. 전투력 외 정찰·채집·마법 탐지 등의 전문성을 활용하는 방향이다.
- [기획 방향/세부 미확정] **최후의 도시 방어전:** 편성 부대를 성벽·성문·마법탑·예비대 등 여러 방어 지점에 배치해 마왕군 침공에 대응하는 별도 콘텐츠를 검토한다. 일반 캐릭터와 상위 지휘관의 협동을 구현하는 방향이다.
- [제안] **시설·생산:** 대장간, 연금술, 병영, 연구소, 치료소 등에 캐릭터를 배치하여 자원·보급의 효율을 얻는 방식.
- [제안] **교역·호송:** 상단·교역로·호위 임무에 전문 캐릭터를 투입하는 방식.
- [제안] 성급과 무관한 직업/적성(정찰, 생산, 회복, 수비, 지휘 등)을 부여해 D~B급이 최고 등급 도달 뒤에도 활용될 수 있게 한다. **같은 등급의 모든 캐릭터를 동일한 지원 능력으로 만들어서는 안 된다.**
- [기존 UI 기준] 공격 지원 2칸 + 패시브 지원 2칸은 이미 마련한 빈 슬롯이다. [미확정] 지원 캐릭터가 실제 전장에 모델로 등장하는지, 자동 공격 이펙트만 제공하는지, 단순 능력치 버프인지와 편성/교체/동시 출격 규칙은 확정되지 않았다.
- [미확정] 탐색의 소요 시간·자동 편성·성공률·보상, 도시 방어의 실시간 전투 여부·부대 수·손실·보상·보스 연동, 시설/호송의 실제 추가 여부는 미정이다. **서브 콘텐츠를 즉시 구현 완료 또는 채택 확정으로 보고하지 않는다.**
- [제안] 모바일 부담을 늘리지 않기 위해 서브 콘텐츠는 메인6분 전투의 방해가 되지 않도록 자동 편성·간편 수령을 고려한다. 동일 캐릭터 파견 시 메인 전투가 막히는 제약 여부는 별도 결정한다.

### 6.5. 수집·영구 성장·경제에서 미확정인 것

1. **뽑기 상품과 분포:** 단차/연차 재화, 무료 뽑기, 등급별 확률·픽업·천장·중복 카드 분포, 특별히 D급 시작인 비야의 중복 획득 방식.

### 6.6. 기획 진행 원칙
