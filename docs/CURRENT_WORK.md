## GAME-004C — 실제 변경

### 전투 이탈/재시작 확인
- 기존 설정창의 즉시 초기화 `새 전투 시작` 연결을 **확인창을 여는 연결**로 바꿨다. 설정창에 `전투 포기 · 결과 확인` 버튼도 추가했다.
- 확인을 열기만 해서는 HP·MP·경험치·보유 스킬·적/탄환·통계·반응 시간·추첨 RNG를 초기화하지 않는다. 기존 RunState의 PAUSED를 사용한다.
- 취소 버튼 또는 확인창의 Esc는 기존 RUNNING 또는 CHOOSING으로 돌아간다. 레벨업 중 취소는 같은 후보·같은 선택 ticket·남은 선택 수를 유지한다.
- 확인 버튼으로 새 전투를 시작한 경우에만 기존 캐릭터로 초기화한다. 캐릭터 데이터 검증에 실패하면 기존 전투/확인 상태를 남긴다. UI가 다시 start를 호출해 두 번 초기화하지 않는다.

### 포기/패배/결과/대기
- RunState에 `ABANDONED`를 추가했다. 이전 enum 값은 유지한다. 중도 포기를 HP0 피해로 위장하지 않고 결과 `outcome="abandoned"`로 구분한다. 실제 HP 소진은 `outcome="defeat"`다.
- 종료 시 결과를 값 복사본으로 고정하고 호출자에게 독립 복사본을 돌려준다. 결과 항목은 기존 레벨·생존 시간·처치·발사·마법 횟수이며 경제 보상/승리 조건은 추가하지 않았다.
- 포기/패배 결과 화면에 `출격 대기로`를 연결했다. READY에서는 시뮬레이션이 진행하지 않는다. 직전 결과는 다음 명시적 출격까지 유지하고, 새 출격 시 기존 초기화 경로를 사용한다.
- 확정 종료 후 미처리 선택을 비우고 선택 ticket을 무효화한다. **확인 전이나 취소 시에는 이 처리를 하지 않는다.**

### 중복/포커스/기존 HUD
- RunState의 단조 증가 `navigation_ticket`과 UI `_menu_revision`으로 오래된 시작·계속·확인·취소·대기 복귀 요청을 거절한다. 이전 결과 버튼이 새 전투를 종료시키거나 연속 확인이 두 번 초기화하지 못하도록 작성했다.
- 확인창 중 앱 포커스가 사라지면 확인 의도만 취소하고 PAUSED/설정 화면을 유지한다. 이전 확인 버튼은 무효가 되고 사용자가 계속하기를 눌러야 한다.
- 확인/결과/대기 중 이동·마법 입력을 해제한다. 기존 마법·반응·피해·타이머는 RUNNING 조건으로 계속 제어한다.
- 기존 `mobile_main.gd`를 수정했으며 별도 UI·시뮬레이션을 새로 만들지 않았다. safe-area, compact HUD, 스크롤 카드, 읽기 전용 보유 스킬 상세는 유지한다.
