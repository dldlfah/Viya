### 1단계 — 데이터 기반 6분 구조

`data/stages.json`의 기본값과 스테이지 번호별 overrides를 기존 RunState가 읽는다. 기본 전투는 **360초**, 체크포인트는 **120·240초**, 최종 보스는 **300초**다. 정예는 각 구간 안의 **110·230초**를 임시값으로 적용했다.

보스를 일찍 잡으면 남은 시간 동안 생존한다. **360초까지 생존하며 보스를 처치한 경우 클리어**, 360초에 보스가 남으면 **시간 초과 종료·클리어 보상 미지급**이다. 이 시간 초과 해석은 한 판6분 한도를 유지하기 위한 구현 결정이다. 보스 이후에도 일반 공세를 유지하며, 적 상한80 안에 보스용 한 자리를 확보했다. 기존 이동/공격/마법의 시간 배율은 유지했다.

### 2단계 — 성장·웨이브 측정

요구XP `(10+(level-1)×6)×3`, 기본 드롭5XP, 18종 후보/무작위3선택을 유지했다. 임시 웨이브는 0~2분 1.6초마다1마리·HP20, 2~4분 2.4초마다2마리·HP28, 4~6분 3초마다3마리·HP36이다. 정예HP140/240·보스HP1600과 적 속도68/80/96은 조정 가능한 임시값이다.

`tests/measure_campaign.gd`가 실제 RunState를5개 시드로 실행했다. 자동 조작은 실제 선택·이동·수집·마법을 사용하며 무적/추가XP를 주지 않는다. 첫 선택은 **10.0~11.8초**, 한 판 선택은 **10~12회**였다. **4회는360초 클리어·289~292처치, 1회는313.2초 보스 구간 패배**였다. 2분까지5회, 4분까지8~9회 선택을 관측했다. 요구XP 변경은 현재 제안하지 않는다. 이는 해당 조작 조건의 측정이며 실기·사용자 재미 검수를 대체하지 않는다.

### 3단계 — 체크포인트와 중단 복원

`user://viya_run.save`에2·4분 체크포인트, 출격, 선택지 표시 전, 선택 확정 후, 일시정지/앱 중단/종료 시 저장한다. 설정의 **저장 후 출격 대기로 → 이어하기**도 연결했다. 재실행 복원은 정지 상태에서 시작하고 명시적으로 계속해야 한다.

HP·MP·쿨다운·캐릭터·보유 스킬·XP·예약 선택·기존 후보·세 난수 상태·시간·스폰 진행·적/탄환/픽업·금화를 정확히 저장한다. 공격 타이머·관통 중복 피격 기록·체력 회복 잔여량도 포함한다. 스킬은 재추첨하지 않으며 낡은 입력 ticket을 새로 무효화한다. 확인 중이던 이탈/재시작 의도와 상세창은 취소하고 안전한 정지 화면으로 복원한다. 짧은 공격 장식·피해/XP 표시·초상화 반응 타이머는 재구성한다.

버전·스테이지/스킬 데이터 지문·SHA-256과 상태 검증 뒤 기존 RunState에만 복원한다. 임시 파일을 완성한 뒤 원자적으로 교체한다. 손상 파일은 자동 초기화하지 않으며 삭제에 취소/확인을 제공한다. 강제 종료나 콜백 미수신 시에는 **마지막 성공한 저장**으로 복원한다. 설정 파일과 영구 금화 파일은 기존 경로를 유지한다.

### 4단계 — 보상 무결성

클리어/패배/포기/시간 초과 결과를 먼저 저장하고 금화를 정산한다. 클리어는 기존 기본100+획득 금화이며 마지막 보스/바닥 금화를 회수한다. 일반10~50·정예/보스100~1000·확률30%는 유지한다. 시간 초과/패배/포기는 미지급이며 다음 스테이지를 열지 않는다.

지급 후 결과 재실행은 재지급하지 않는다. 이미 지급한 스테이지의 옛 활성 체크포인트는 복원을 거절한다. 종료 결과가 저장되지 않으면 지급/다음 출격을 막고 재시도를 제공한다. 복원 후90스텝 전투 동일성, 실제 선택 보존, 파일 손상·불완전 상태 거절, 중단/재시도와 지급 후 재실행을 검증했다.
