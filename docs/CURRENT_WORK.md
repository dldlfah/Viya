### 구현 완료

- 시작 시 **VIYA 임시 메인 로비**를 연다. 출격/이어하기·보유 골드·계정 공격 특성과 특성창 접근을 제공한다. 이전 종료 상태는 복구·정산 후 로비로 돌아가며 결과를 보존한다. 정산/저장 실패는 기존 복구·재시도 화면으로 처리한다.
- 특성창은 **공격·방어·회복** 탭을 둔다. 방어와 회복의 내용 영역은 실제 빈칸이다. 공격력 강화만3단계이며 순서대로 구매한다.

| 공격 단계 | 해당 단계 골드 비용 | 임시 누적 공격력 증가 |
| --- | ---: | ---: |
| 1단계 | 1,000 | +5% |
| 2단계 | 50,000 | +10% |
| 3단계 | 1,000,000 | +15% |

비용은 사용자 지정값이며 총합1,051,000골드다. 강화 효과는 “임의로” 요청에 따른 임시값이다. `account_talents.gd`에서 관리한다. 현재 로컬 계정 저장을 모든 캐릭터가 공유하며, 실제 추가 캐릭터/로그인·서버 동기화는 만들지 않았다. 별도 캐릭터 fixture로 같은 계정 배율 적용을 검증했다.

새 전투는 계정 특성을 받고 기존 전투 공격력 패시브와 곱해 모든 실제 공격/필살기에 적용한다. 강화 미리보기와 성장 현황은 같은 프로파일을 읽는다. 이어하기 전투는 **출격 당시 특성**을 보존한다. 전투를 저장해 로비로 나온 뒤 구매하면 다음 새 전투와 확인 후 재시작부터 최신 단계가 적용된다.

### 저장과 구매 무결성

기존 `user://viya_gold.cfg`에 계정 schema1/공격 단계를 함께 저장한다. 골드 차감과 단계 증가는 한 임시 파일/rename으로 처리하고 성공 후에만 메모리를 갱신한다. 기존 골드 파일은 잔액·스테이지·정산 ID를 유지하고 특성0으로 읽는다. 클리어 정산도 특성과 다른 키를 보존한다.

골드 부족·단계 건너뛰기·상한·중복 요청·이전 메뉴 콜백·전투 중 구매·손상 데이터·저장 실패를 차단한다. 오래된 다른 계정 인스턴스의 순차 요청이 최신 잔액/강화 단계를 덮어쓰지 않는지도 검사했다. 온라인 거래 잠금/동기화 시스템은 범위에 없다.

전투 저장4는 출격 당시 공격 특성 단계를 보존한다. 알려진 GAME-009/010/011 저장1·2·3은 기존 능력치 보존을 위해 계정 특성0으로 변환한다. HP/MP·적·후보·시간·난수·보상 무결성을 유지한다. 실제 저장1의 HP73/MP48.5/기지급117금화와 저장2의27개체, 저장3의190개체 복원을 확인했다. 새 프로세스에서도 계정1단계/잔액1,050,000·전투 배율1.05·사용 후 MP60이 유지됐다. 렌더 시험의 금화 지급은 격리된 fixture에만 적용했고 새 계정의 실제 시작 골드는0이다.
