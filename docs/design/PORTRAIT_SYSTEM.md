# VIYA 전투 초상화 연결 안내

기준일: 2026-11-25 (KST). 네 가지 표정의 **상태 전환과 원화 연결 시스템**이다. 현재 승인된 표정 원화가 연결된 상태는 아니며, 새 얼굴·의상·원화를 생성하지 않았다.

| 표정 키 | 표현 | 실제 전투 연결 | 임시 표시 시간 |
| --- | --- | --- | --- |
| `normal` | 평상시 전투 집중 | 반응 종료 후 기본 상태 | 기본 유지 |
| `hurt` | 피격 고통 | 실제 HP가 감소한 피격 | 0.55초 |
| `heal` | 체력 아이템 사용 후 안도 | 기존 HP 보급품을 소비한 순간 | 1.00초 |
| `levelup` | 레벨업 기쁨 | 기존 XP 성장/선택창 이벤트 | 1.20초 |

네 번째는 기존 기획서의 **레벨업 시 들뜬 표정**을 따른다. 회복 표정은 HP 아이템 소비 반응이다. 자연 회복·처치 회복·MP 아이템이 이를 반복해서 발생시키지 않는다. HP가 가득 차 있어도 실제 아이템을 소비하면 반응하지만, HP/회복 수치는 기존 실제 정산만 표시한다.

표시 우선순위는 종료 → 지속 고통/피격 → HP 아이템 → 기존 마법 피드백 → 레벨업 → 저체력 안내/기본이다. 가려진 반응은 표시 시간을 보존한다. 마법의 기존 문구/색상은 유지하되 초상화는 `normal`을 사용한다. 저체력 안내도 별도로 계속 표시하며 다섯 번째 표정을 만들지 않는다. 종료 화면은 기존 종료 안내와 기본 초상화를 사용한다.

## 원화 연결

[portrait_presentation.json](../../data/portrait_presentation.json)의 `viya` 아래 네 경로에 승인된 자산의 `res://` 경로를 지정한다. 현재 네 값은 모두 공백이다. 기존 [presentation_slots.json](../../data/presentation_slots.json)의 53개 공용 슬롯과 승인 원본은 변경하지 않았다.

- 각 경로에는 `Texture2D`를 지정할 수 있다. PNG/WebP 등의 원본은 Godot에서 정상 가져오기되어야 한다.
- `SpriteFrames`도 연결할 수 있다. 해당 표정 키의 애니메이션 또는 `idle`의 첫 프레임을 사용한다. 프레임 애니메이션 재생을 구현했다는 의미는 아니다.
- 네 이미지의 얼굴 위치·크롭·투명 여백을 통일하는 것을 권장한다. 화면은 종횡비를 보존하고 원화를 늘이거나 뒤집지 않는다.
- 선택 표정 → 기존 공용 SpriteFrames의 일치 표정 → 준비된 기본 원화/기존 공용 초상화 순으로 대체한다. 모두 없으면 기존 문구·색상·테두리 임시 표시를 유지한다.
- 원화는 완전 불투명하게 표시하고 반응/저체력 안내는 아래쪽에 배치한다. 초상화와 문구는 이동·마법 터치를 가로채지 않는다.
- 자산은 경로별로 캐시한다. 같은 경로의 파일을 교체한 뒤에는 게임을 다시 실행해 확인한다.

`expression_has_art`는 선택 표정에 해당하는 자산이 연결됐는지 진단하는 속성이다. 기본 원화로 대체된 것을 해당 표정 원화 완성으로 간주하지 않는다. 자동 시험의 단색 텍스처는 연결 확인 전용이며 게임 자산으로 등록하지 않는다.

## 상태·이어하기

기존 `FeedbackState`가 네 반응 시간을 관리한다. UI는 상태를 읽고 자산을 선택하며 시계를 진행시키지 않는다. 정지·스킬 선택 중에는 시간이 멈춘다. 새 출격/종료는 반응을 초기화하고, 저장 복원은 과거 피격·회복·레벨업 표정을 다시 재생하지 않는다. HP/MP·스킬·후보·보상·난수와 기존 저장22 규칙은 유지한다.

독 같은 지속 상태이상의 표정 연결용으로 `simulation.feedback.set_persistent_pain(true/false)`를 준비했다. `true` 동안 고통 표정을 유지하고 대기 반응 시간을 보존한다. **독 피해·지형·지속시간 시스템은 이번 작업에 추가하지 않았다.** 향후 실제 상태이상 소유자가 진입/해제 시 호출하고, 저장 복원 뒤 현재 상태이상으로 다시 적용해야 한다. 이 표정 플래그가 HP 피해나 상태이상 저장의 소유자가 되어서는 안 된다.
