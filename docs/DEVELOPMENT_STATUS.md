## 3. 사용자 확정사항과 임시 구현값

### 3.1. 계속 보존할 방향

- 모바일 가로형 서바이버 게임, 전장 주력 한 명. 초기 실제 캐릭터 데이터는 비야다. 기존 BREAKERS 본편은 변경하지 않는다.
- 비야는 **ART-001 승인 시안 확정 단계에서 보류**한다. 원화 정합화·3D·리깅·애니메이션·코스튬은 게임 작업의 선행조건이 아니다.
- 레벨업은 기본 서로 다른 무작위 후보3개 중1개 선택. 공통 공격8 + 현재 캐릭터 공격1 + 공통 패시브8(저항 제외) + 현재 캐릭터 필살기 강화1 = **18종**.
- 공통16종을 공유하고 캐릭터 전용2종과 고유 액티브 설정을 캐릭터 데이터로 교체하는 구조다. 다른 캐릭터 콘텐츠가 완성됐다는 뜻은 아니다.
- 모든 스킬 이름은 **`[임시]`**. 보유 공격/패시브 두 줄, 고유 마법 별도 수동 버튼. 고유 액티브 자체를 19번째 레벨업 후보로 추가하지 않는다.
- 레벨업 **요구 경험치**를 기존의3배로 높였다. 획득 경험치를3배 지급하는 변경이 아니다. 기본 드롭5XP와 경험치 패시브 계수는 당시 변경 없이 유지했다.
- 서포터는 공격2칸·패시브2칸의 빈 자리만. 지원 공격·추가 스탯·속성 저항·수집·뽑기·과금은 미구현/보류다.
- 환경설정과 상태 반응 방향을 유지한다. 현재 반응은 얼굴 그림이 아닌 문구·테두리 대역이다.

### 3.2. 임시값의 경계

공격/패시브 동시 장착 각4칸, 시작 소총Lv.1, 강화상한Lv.5, 후보 동일확률, 개별 이름·공격 형태·피해량·패시브 계수, 마법 자원·범위, 전장·적 수, 반응 시간·저체력 경계, 이번 전장 표시 시간·개수 상한은 시험값이다. **후보8종을 장착8칸으로 해석하지 않는다.** 시제품이 코드에 있다는 이유로 최종 콘텐츠·밸런스·아트 승인을 부여하지 않는다.

## 6. 기능별 현재 상태

아래의 '연결'은 코드 경로를 뜻하며 실제 엔진/기기 합격을 뜻하지 않는다.

### 6.1. 기본 전투·한 판 흐름

- 상태는 READY / RUNNING / PAUSED / DEFEAT / CHOOSING / ABANDONED. GAME-004C에서 마지막 상태를 추가했고 이전 enum값은 유지했다. 승리/보스는 없다.
- 출격은 캐릭터 후보·마법 검증 후 위치/HP/통계/적·탄환·픽업·효과/성장·마법·반응을 초기화한다. GAME-004D는 표시 데이터 초기화를 여기에 추가했다. 잘못된 캐릭터를 비야로 조용히 대체하지 않는다.
- 터치 이동·PC WASD/방향키/마우스, 경계 제한, 적 생성/추적, 최근접 자동 조준, 선분 탄환 충돌, 관통탄 동일 적 중복 피격 차단이 있다.
- 피격 무적 간격과 HP0 패배, 결과 통계, 재시작 경로가 있다. 설정 정지·포커스 상실 입력 해제·전체 음량 저장은 작성됐으나 전투 음원은 없다.
- GAME-004C의 확인·취소·포기/패배·대기는 6.7절, GAME-004D의 실제 사건 표시는 6.8절을 따른다.

### 6.2. 성장·후보 선택

- 실제 적 사망에 XP픽업 생성, 접근하면 흡수. 픽업 상한 초과 시 마지막 픽업에 값을 합쳐 보존한다.
- 여러 레벨의 선택을 예약하고 CHOOSING으로 정지한다. 전투와 추첨 RNG는 분리되어 있으며 분류별1개 강제가 아닌 전체 유효 후보의 중복 없는 무작위3개다.
- 신규 획득/보유 강화, 장착·강화 상한 필터가 있다. 설정·상세·이탈 취소는 후보를 다시 뽑지 않는다.
- 성장 ticket은 재시작에도 재사용하지 않는다. 이전 전투·이전 선택·중복 콜백을 거절한다. 다중 선택은 순서대로 처리한다.
- 유효 후보1~2종이면 남은 수만 보여준다. 0종은 새 스킬/보상 없이 '성장 완료 · 계속'으로 복귀하는 임시 정책이다.
- 기본 소총Lv.1은 공격4칸 중1칸을 차지한다. 캐릭터 자동 공격도 공격칸, 필살기 강화는 별도 영역이다.

### 6.5. 상태 반응 영역

- 우선순위: 종료 > 피격 > 마법 > 레벨업 > 저체력 > 기본. 낮은 우선순위 반응은 가려진 동안 시간을 쓰지 않으며 종류별 한 상태만 보관한다.
- 수락된 피해·성공한 마법·실제 선택ticket에 반응한다. 거절된 입력이 반응을 재발급하지 않도록 작성했다.
- 저체력 경고는 다른 반응 중에도 별도로 유지한다. 정지·선택·확인은 시간 보존, 종료는 대기 반응 제거, 재출격은 초기화다.
- 완성 얼굴·눈깜빡임·전신 동작은 없다. 문구/색/테두리를 최종 라이브 초상화로 보고하지 않는다. 독/화염 지형의 지속 고통 반응은 아이디어이며 해당 전투 시스템은 미구현이다.

### 6.6. 모바일 HUD·읽기 전용 상세

- HudLayout이 상단·전장·이동·하단·모달을 함께 계산한다. 넓으면 하단 가로 배치, 좁으면 상태/마법과 스킬 두 줄을 나누는 compact 배치다.
- Android/iOS 안전영역의 논리 좌표 변환과 빈 값 대체 경로가 있다. 노치/카메라 홀 실기 합격은 아니다.
- 리사이즈는 이동/마법 소유권 해제·낡은 요청 무효화만 하며 XP·스킬·후보·MP·쿨다운을 초기화하지 않는다.
- 보유 슬롯은 전체 임시명·보유 레벨·설명의 읽기 전용 정지 화면을 연다. 빈 슬롯은 비활성. 획득/강화/마법 발동은 하지 않으며 닫으면 이전 상태로 복귀한다.
- 넓은 선택창3열/좁은 창1열 스크롤, 후보·콜백 재사용. 긴 문구·최소크기·실제 터치 도달·클리핑은 미검증이다.

### 6.7. GAME-004C — 이탈·재시작 확인과 결과→대기

권위는 RunState의 `navigation_ticket`, `transition_action`, `_finished_result`이며 UI는 `_menu_revision`으로 콜백을 검증한다. GAME-004D는 이 함수들을 바꾸지 않았다.

| 입력/상태 | 처리 | 보존 경계 |
| --- | --- | --- |
| 설정의 새 전투 | request_transition("restart") → 확인 | 확인 전에 HP·MP·XP·스킬·선택·통계 초기화 금지 |
| 전투 포기 | request_transition("leave") → 확인 | 즉시 패배/종료 처리하지 않음 |
| 취소/확인창Esc | cancel_transition → 이전 RUNNING/CHOOSING | 동일 후보·성장ticket·남은 선택·RNG·타이머 보존 |
| 재시작 확인 | 검증 후 현재 캐릭터로 start1회 | 검증 실패는 기존 전투/확인 유지. UI의 이중 start 금지 |
| 포기 확인 | ABANDONED, outcome="abandoned" | HP0 피해로 위장하지 않음 |
| 실제 체력 소진 | DEFEAT, outcome="defeat" | 포기와 다른 결과 원인·제목 |
| 결과→대기 | terminal에서만 return_to_ready | READY 시간 정지. 새 출격까지 고정 결과 보존 |
| 확인 중 앱 중단 | intent만 취소·ticket무효화·PAUSED유지 | 자동 재개 금지, 명시적 계속하기 |
| 이전/중복 화면 요청 | navigation_ticket+menu_revision 검사 | 새 전투를 과거 버튼으로 종료/초기화 금지 |

확인 전과 취소에는 성장 offer/ticket을 건드리지 않는다. 종료 확정 시에만 pending/offer를 비우고 ticket을 무효화한다. 결과는 독립 값 복사본으로 반환한다. 결과 제목은 포기와 실제 패배를 구분한다. 확인창은 취소에 초기 포커스를 두며 내부 begin_run은 시험 설정에도 사용한다. 실제 버튼/키 입력은 여전히 엔진 미검증이다. 승리·경제·영구 보상·저장복구는 추가하지 않았다.

### 6.8. GAME-004D — 실제 타격·처치·수집 XP 전장 피드백

**경로:** 기존 RunState의 확정된 사건 → `CombatCues`의 표시 데이터 → 기존 `BattleView`의 색·숫자·작은 링. CombatCues는 게임 상태나 난수 소유자가 아니다.

| 사건 | 발생 위치와 표시 | 성공으로 오인하면 안 되는 것 |
| --- | --- | --- |
| 적 HP 감소 | `_damage_enemy`의 기존 HP 차감 이후 강조·피해 숫자 | 발사 시도·없는 대상·이미 제거된 ID는 타격이 아님 |
| 실제 치명타 | 기존 치명타 분기를 재사용, 숫자색 및 `!` | 표시용 치명타를 별도로 추첨하지 않음 |
| 실제 적 제거 | 적 제거·처치수 증가 후 소멸 링 | 이펙트 발생 자체는 처치가 아님 |
| 실제 XP 흡수 | `_collect_pickups`에서 기존 XP 부여 후 `+XP` | 드롭 생성·원거리 픽업·임의 grant_xp 호출은 수집 표시 아님 |

- 표시 피해량은 `기존HP - max(0, 차감후HP)`로 계산한 **실제 제거한 HP**다. 원래 피해 산식/HP 차감은 그대로이며, 남은 HP를 넘는 과잉 피해는 화면 숫자에 더하지 않는다.
- 동일 적의 짧은 연속 타격은 숫자 하나에 합산한다. 그 안에 치명타가 하나라도 있으면 강조한다. 새로운 확률 판정은 없다.
- 실제 수집된 XP는 경험치 패시브가 반영된 소수값을 유지한다. 짧게 이어진 수집을 합산하고 화면은 소수둘째자리로 표현한다. 게임 XP 자체를 반올림하지 않는다.
- 수집으로 바로 CHOOSING이 되더라도 해당 수집 표시는 기록한다. 시간은 RUNNING 가드 이후 시뮬레이션 dt로만 진행하므로 선택·상세·설정·확인·결과·대기에서 멈추고 새 출격 성공 시 초기화한다.
- 표시 이벤트 최대48, 피격 강조 최대80. 상한을 넘으면 오래된 **표시만** 지운다. 실제 피해/처치/드롭을 제한하는 로직은 아니다. 실제 게임에서의 보상 보존 시험은 작성됐으나 아직 실행하지 않았다.
- 같은 전장 Control의 draw 호출을 사용한다. 개별 Label·입자·Timer·Tween을 계속 만들지 않는다. 기존 clip_contents와 화면 밖 제외를 유지한다. 새 아트·정식 연출·음원은 없다.
- 진단용 enabled 전환은 표시만 비우며 게임 상태에 관여하지 않는다. 사용자 환경설정에 새 옵션을 추가한 것은 아니다.
- 이번 RunState의 기존 함수30개는 바이트 단위로 보존했다. 변경한4개는 start/step/_collect_pickups/_damage_enemy이며 검토한 추가 표시행을 제거하면 이전 Git blob과 정확히 같다. 이 **소스 대조 PASS**는 런타임 동등성 시험 PASS가 아니다.
