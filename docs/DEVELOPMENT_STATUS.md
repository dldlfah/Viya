## 3. 사용자 확정사항과 임시 구현값의 경계

### 3.1. 계속 보존할 확정 방향

- 모바일 가로형 서바이버 게임. 전장의 주력은 한 명이며 초기 실제 캐릭터 데이터는 비야다. 기존 BREAKERS 게임의 장르·코드·아트는 변경하지 않는다.
- 비야는 **ART-001 승인 시안 확정 단계에서 일단 마무리**한다. 방향별 원화 정합화, 3D, 리깅, 애니메이션, 코스튬 제작은 보류이며 게임 작업의 선행조건이 아니다.
- 레벨업은 기본 **서로 다른 무작위 후보 3개 중 1개 선택**. 모든 클래스 공통 공격 8종 + 현재 캐릭터 전용 공격 1종 + 공통 패시브 8종(저항 제외) + 현재 캐릭터 필살기 강화 1종 = **18종**.
- 다른 주력 캐릭터를 추가할 때 공통 16종은 공유하고 전용 공격·필살기 강화 2종과 고유 마법 설정을 캐릭터 데이터에서 교체한다. 그 구조가 있다는 것이 다른 캐릭터 콘텐츠가 완성됐다는 뜻은 아니다.
- 모든 스킬 이름은 **`[임시]`**로 표시한다. 공격·패시브 보유 상태는 두 줄, 고유 마법은 별도 수동 버튼을 사용한다. 고유 액티브 자체를 19번째 레벨업 후보로 추가하지 않는다.
- 레벨업 **요구 경험치**를 이전보다 3배로 높인다. 획득 경험치를 3배 지급하는 것이 아니다.
- 서포터는 공격 지원 2칸·패시브 지원 2칸의 빈 자리만 둔다. 지원 공격·추가 능력치·속성 저항·수집·뽑기는 아직 만들지 않는다.
- 환경설정과 상태 반응 방향을 보존한다. 현재 상태 반응은 얼굴 그림이 아닌 문구·테두리 대역이다.

### 3.2. 확정 콘텐츠로 승격하면 안 되는 임시값

공격/패시브 동시 장착 각 4칸, 소총 Lv.1 기본 장착, 스킬 강화 상한 Lv.5, 후보 동일 확률, 개별 스킬명·공격 형태·피해량·패시브 계수, 마법 MP·쿨다운·범위, 적 수·전장 크기, 저체력 경계·반응 시간은 구현 시험값이다. **18종 후보 수를 공격8칸·패시브8칸으로 해석하지 않는다.** 이후 수치 변경 시 PLANNED_WORK의 확정사항과 구분한다.

## 6. 기능별 현재 개발 상태

아래의 '연결'은 코드 경로가 작성되어 있다는 뜻이다. 표의 모든 게임 기능은 실제 엔진/실기 동작 NOT_VERIFIED를 전제로 한다.

### 6.1. 기본 전투와 한 판 흐름

- 상태는 `READY`, `RUNNING`, `PAUSED`, `DEFEAT`, `CHOOSING`. 아직 별도의 승리·중도 포기 상태를 추가한 단계가 아니다.
- 출격 시 시작 위치·HP·통계·적/탄환/픽업/효과·성장/마법/반응을 초기화한다. 캐릭터 후보와 마법 설정을 먼저 검증하고 잘못된 캐릭터를 비야로 조용히 바꾸지 않는다.
- 터치 이동, PC WASD/방향키 및 마우스 드래그, 경계 제한, 적 생성·접근, 사거리 안 가장 가까운 적 자동 조준, 선분 기반 탄환 충돌, 관통탄의 같은 적 재타격 방지 코드를 보유한다.
- 피격은 무적 간격을 사용하고 HP0이면 DEFEAT. 결과에는 레벨·생존 시간·처치·발사·마법 사용 횟수를 표시하는 코드가 있다. 다시 출격은 연결되어 있다.
- 환경설정 정지/재개, 앱 포커스 상실 시 정지·입력 해제, 음량 저장은 작성되어 있다. 실제 전투 음원은 미탑재다.
- **아직 없음:** 진행 중 새 전투/이탈의 확인·취소, 중도 이탈과 패배의 구분, 결과 → 출격 대기 복귀의 완결된 경로. 이 부분이 GAME-004C다.

### 6.2. 성장과 후보 선택

- 적 사망 시 XP 픽업이 생성되고 접근 시 흡수된다. 픽업 상한 초과 시 마지막 픽업에 값을 합쳐 보존하는 코드다.
- 요구 XP 충족 시 여러 레벨의 선택을 예약하고 CHOOSING으로 정지한다. 전투 RNG와 선택 RNG를 분리하고, 후보는 각 분류 1개 강제가 아니라 유효 목록 전체에서 중복 없이 추첨한다.
- 처음 고르면 신규 획득, 같은 ID를 다시 고르면 강화. 임시 슬롯 상한·강화 상한에 도달한 후보는 제외한다. 설정창 복귀는 같은 후보를 유지한다.
- 선택 ticket은 재시작을 거쳐도 재사용하지 않는다. 이미 처리한 카드/이전 선택/이전 전투 콜백을 거절한다. 여러 선택은 순차 처리한다.
- 유효 후보 1~2종이면 그 수만 표시한다. 0종이면 추가 스킬·보상 없이 '성장 완료 · 계속'으로 복귀하는 **임시 예외 정책**이다.
- 소총 Lv.1은 시작부터 임시 공격 4칸 중 하나를 차지한다. 비야 전용 공격도 공격칸을 사용한다. 필살기 강화는 별도 영역이며 패시브칸을 점유하지 않는다.

### 6.5. 반응 영역과 결과

- 우선순위: **전투 종료 > 피격 > 마법 > 레벨업 > 저체력 > 기본**. 낮은 우선순위 반응은 가려진 동안 시간을 소비하지 않는다. 종류마다 한 상태만 보관한다.
- 실제 피해 수락/마법 성공/선택 ticket을 반응과 연결한다. 거절된 중복 요청이 반응을 재발급하지 않도록 작성했다.
- 저체력 경고는 다른 반응 중에도 별도 유지. 설정·선택·앱 중단에는 반응 시간이 멈추고, 사망은 대기 반응을 비우며 재시작은 기본 상태로 돌아간다.
- **완성된 비야 표정 원화·눈깜빡임·전신 애니메이션은 없다.** 현재 `feedback_panel.gd`의 문구/색/테두리 표시를 최종 라이브 초상화로 보고하지 않는다. 독·화염 지형에 따른 지속 고통은 기존 아이디어이며 현재 반응 소스에 해당 전투 시스템은 없다.

### 6.6. 모바일 HUD·상세창

- `hud_layout.gd`가 상단·전장·이동·하단·모달을 함께 계산한다. 넓은 화면은 하단 가로 배치, 좁은 화면은 상태/마법과 스킬 두 줄을 분리한 compact 배치다.
- Android/iOS 안전영역을 논리 UI로 변환하는 코드와 빈 값 대체 경로가 있다. 노치·카메라 홀 대응의 실기 합격 증거는 없다.
- 크기 변경은 이동·마법 입력을 해제하고 낡은 마법 요청을 무효화한다. XP·보유 스킬·후보·MP·쿨다운을 초기화하는 작업이 아니다.
- 보유 슬롯을 누르면 전체 `[임시]` 이름·레벨·설명을 보는 읽기 전용 상세창. 빈 슬롯은 비활성화. 전투 정지·이전 상태 복귀를 기존 소유자에 연결하고 획득/강화/발동은 금지했다.
- 레벨업 카드는 넓으면 3열, 공간이 좁으면 1열 세로 스크롤. 후보·콜백을 재사용하며 재추첨하지 않는다.
- 실제 화면에서 텍스트가 모두 읽히는지, 컨테이너 최소 크기가 배치값을 넘지 않는지, 터치가 올바른 컨트롤에 도달하는지는 미검증이다. 시험 입력 해상도를 지원 보증 해상도로 쓰지 않는다.

### 8.3. 실행 경로와 주의

```sh

# GAME-004B 전용 변경 소스 검사. 엔진 검사를 대신하지 않는다.
python tools/check_mobile_hud.py
```

[check_project.py](../tools/check_project.py)는 파일·성장·마법·반응 소스 검사 후 엔진이 있으면 import → 기반 → 성장 → 마법 → 반응 → 모바일 HUD 시험 → 시작 장면 부팅 순서로 실행하도록 작성되어 있다. `check_mobile_hud.py`의 전용 정적 검사는 별도 명령이다. 검사기는 사용자 저장 경로와 분리된 임시 데이터 경로를 사용한다. 엔진 없음은 종료2/NOT_VERIFIED, 확인된 결함은 FAIL로 구분한다. 유료 GitHub Actions는 사용하지 않는다.

현재까지의 기록상 실제 Godot 실행 파일 확보·엔진 시험 실행에 성공한 증거가 없다. 이번 문서 작업은 엔진 설치·실행을 다시 시도하는 요청이 아니므로 환경 가능성이나 실패 원인을 새로 단정하지 않는다. 다음 개발 세션에서 엔진을 사용할 수 있으면 첫 실제 오류부터 확인하되, 매번 사용자에게 Pull·로그 제출을 요구하며 개발을 중단하지 않는다.
