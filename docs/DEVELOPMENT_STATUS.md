## 2. 문서 역할과 운영

README → AGENTS → 제작 스킬 → CURRENT_WORK → 본 문서 → PLANNED_WORK → GAME_DESIGN_BASELINE/ART_APPROVAL → NEXT_TASK 순서로 확인한다. CURRENT는 현재 사실, 본 문서는 누적 상태/검증/미완성, PLANNED는 확정·후속·보류 계획, NEXT는 다음 연결된 게임 단위 하나다. 오래된 AGENTS/스킬의 체크포인트 SHA는 최신 CURRENT/본 문서/NEXT로 대체된다.

같은 작업 브랜치에서 HEAD와 동시 변경을 확인해 보존한다. main 자동 병합·force push·기존 변경 덮어쓰기·유료 Actions·외부 생성 크레딧 소비는 하지 않는다. 실제 연결되지 않은 코드나 문서/검사 개수를 게임 완성으로 세지 않는다. 의미 있는 업데이트 뒤 CURRENT·본 문서·NEXT를 함께 갱신한다.

## 3. 사용자 확정사항과 임시값

모바일 가로 서바이버, 주력1명, 현재 캐릭터 데이터는 비야다. 레벨업은 **공통 공격8 + 캐릭터 공격1 + 공통 패시브8(저항 제외) + 캐릭터 필살기 강화1 = 18종**, 기본적으로 중복 없는 무작위3개 중1개 선택이다. 공통16종은 공유하고 캐릭터 종속2종/고유 마법을 캐릭터 데이터로 교체한다. 다른 캐릭터 콘텐츠가 완성된 것은 아니다.

전 스킬명은 `[임시]`, 보유 공격/패시브는 두 줄, 고유 마법은 수동 버튼/PC F다. 고유 마법 자체를 19번째 후보로 추가하지 않는다. 요구 XP는 `(10+(현재레벨-1)×6)×3`, 드롭 기본5XP다. 지원은 공격2칸·패시브2칸의 **빈 자리만** 존재한다.

공격/패시브 동시 장착 각4칸, 시작 소총Lv.1, 강화상한5, 후보 동일확률, 스킬 효과/수치·전장·적·마법 자원·표시 시간은 시험값이다. **후보8종과 장착8칸은 다른 개념**이다. 원화·3D·리깅·코스튬·수집·뽑기·경제·서포터 효과는 별도 재개 지시 없이 만들지 않는다.

## 6. 기능별 현재 상태

아래는 작성·연결된 코드 범위이며 실제 엔진/모바일 미검증을 전제로 한다.

### 기본 전투·진행

READY/RUNNING/PAUSED/DEFEAT/CHOOSING/ABANDONED를 구분한다. 출격은 캐릭터 후보/마법 데이터 검증 후 위치·HP·통계·적/탄환/픽업/효과·성장/마법/반응을 초기화한다. 잘못된 캐릭터를 비야로 조용히 교체하지 않는다. 입력·경계·적 추적·최근접 자동사격·선분 탄환 충돌·관통 중복 피해 방지·피격 무적을 작성했다.

설정의 재시작/포기는 즉시 초기화가 아닌 확인창이다. 취소는 기존 상태 또는 같은 레벨업 후보/ticket으로 복귀한다. 확정 종료에만 선택을 비우고 ticket을 무효화한다. 포기는 HP0을 만들지 않고 ABANDONED로 구분하며 결과를 독립 복사본으로 고정한다. 결과→대기에서는 시간을 진행하지 않고 명시적 출격 전까지 결과를 보존한다. 확인 중 포커스 상실은 의도만 취소하고 PAUSED를 유지한다. navigation_ticket/menu_revision은 낡은 화면 요청을 막는다.

### 성장과 18종

처치 픽업→접근 흡수→레벨업 CHOOSING→선택→강화→전투 경로다. 전투 RNG와 후보 RNG를 분리한다. 신규 획득/기존 강화, 임시 장착/강화 상한 필터, 복수 레벨 선택 순차 처리, 낡은/중복 선택 거절을 작성했다. 후보1~2개는 남은 수만 표시하고0개는 추가 보상 없이 계속하는 임시 정책이다. 기본 소총Lv.1은 공격4칸 중1칸, 비야 자동 공격도 공격칸, 필살기 강화는 별도 영역이다.

`viya_crimson_wave` / `[임시] 진홍 파동`: 버튼/F→캐릭터/phase/ticket/MP/쿨다운→자원1회 차감→범위 피해→기존 처치/XP→HUD. 강화0부터 사용하며 선택으로 MP/쿨다운을 리셋하지 않는다. 빈 곳 발동/소비는 임시 정책이다. 이동/마법 손가락을 분리하고 정지/선택/확인/결과/대기에서는 발동과 시간을 차단한다.

반응 우선순위는 종료>피격>마법>레벨업>저체력>기본. 가려진 낮은 우선순위는 시간을 보존하고 저체력 경고를 별도 유지한다. 현재 문구·색·테두리 대역이지 얼굴 표정 원화가 아니다.

CombatCues는 실제 HP 차감 뒤 피해 숫자·치명타, 실제 제거 뒤 처치 흔적, 픽업 수집/XP 부여 뒤 `+XP`를 기록한다. 과잉 피해를 실제 제거 HP에 더하지 않고 기존 치명타 결과를 재사용한다. 드롭 생성/임의 XP 부여를 수집 성공으로 표시하지 않는다. 표시는 개수/수명 제한, 시뮬레이션 시간 정지·재출격 초기화를 사용하고 초과 시 표시만 버린다. View는 읽기 전용 직접 그리기이며 노드/Timer를 계속 생성하지 않는다.

### 모바일 HUD·상세창·이번 가드

공유 배치로 상단·전장·이동 허용영역·하단·모달을 계산한다. 좁으면 compact, 카드는3열 또는1열 스크롤이다. 안전영역 변환과 빈 값 대체, 리사이즈 입력 해제, 후보/XP/자원 보존을 작성했다. 컨테이너 최소크기/실제 화면·터치 검증은 미수행이다.

보유 스킬 상세는 읽기 전용 PAUSED다. 빈 칸은 비활성, 닫기/포커스 중단은 기존 복귀 경로를 사용한다. **이번에는 닫기 Callable에도 navigation_ticket과 menu_revision을 묶었다.** 현재 상세창이 열려 있다는 이유만으로 이전 창/이전 전투의 닫기를 수락하지 않는다. Esc는 현재 식별번호로 닫는다.

## 8. 검증 기록과 이번 실제 시험

과거 [validation 디렉터리](validation)의 GAME001/002/003/004/004B/004C/004D 보고서는 해당 소스의 정적/데이터 검사 증거다. 이전 파일7/13/16개 검사나 단계별 대조시험을 현재 전체 검사로 재사용하지 않는다. GAME004 이후 전체 회귀 미실행 기록은 유지한다.

## 9. 실행환경 해결 진행

현재 GitHub 쓰기 경로를 사용해 수정 코드를 원격 커밋 체인에 보존하는 단계와, Godot 실제 실행은 구분한다. 도구 존재/계정 push권한/커밋 객체 생성/브랜치 HEAD 갱신/파일 재조회는 각각 다른 확인이다.

`tools/bootstrap_godot.py`는 Linux x86_64 개발환경용 고정 **4.7.2-stable** 다운로드·캐시·체크섬·버전 확인을 준비했다. 출처는 [공식 release](https://github.com/godotengine/godot-builds/releases/tag/4.7.2-stable), ZIP SHA256은 `cadd3204e728a35d3f13adb7fd0d7902636b79f6b95c40c265eb73b6c35329e4`다. 버전 확인 후 `--check`로 기존 프로젝트 검사기를 호출한다. `--archive`는 같은 체크섬의 준비된 공식 ZIP을 받는다. 임의 미러·sudo·credentials·유료 CI·사용자 PC 조작은 없다.

**실제 수행:** Python 구문과 `--help`는 PASS. 준비 스크립트를 실행했으나 DNS 오류 `Temporary failure in name resolution`로 종료2. [실제 실패 로그](validation/GAME004_ENVIRONMENT_ATTEMPT.log). **Godot 설치/네이티브 버전 실행/프로젝트 실행은 못 했고 Codex 계정 환경은 생성하지 않았다.** 스크립트 존재를 개발환경 구축 완료로 보고하지 않는다.

## 10. 아트·자산과 미완성

ART-001 `a_highly_detailed_layered_production_modeling_d.png`가 승인 기준이다. 방향별 파생 이미지는 단일모델의 정확한 투영이 아니며 정합 최종 미승인이다. Tripo 실패, SAM GLB의 시각 미합격/비리깅, R1/R2의 전체 재생성 실패와 바뀐 소매/장식/다리/170cm·신체치수 미승인을 보존한다. 논리 파츠14개가 실제 분리 메시를 의미하지 않는다.

현재 원화·3D·리그·애니메이션·코스튬 제작은 보류다. 재개 지시 때만 PLANNED_WORK의 Higgsfield 참조/모델/마스크 고정·한 부위 편집·영역 밖 원본 보존/차이 검수를 따른다. GitHub의 QA 축소JPEG2개와 외부 PNG/GLB/ZIP 링크를 구분한다. 이번에 원본 바이너리를 추가로 저장하거나 외부 URL/현재 잔액/배포권을 다시 검증하지 않았다.

그 밖의 미완성: 실제 게임 구동/모바일 HUD·안전영역/다중터치/성능, APK/iOS 내보내기·JSON/폰트 포함, 최종 캐릭터·초상화 반응·전투 음원, 보스·승리·스테이지 목표·독/화염지형, 서포터 공격/능력치·수집·뽑기·과금·영구 성장/보상·중단 저장복구. 음량 저장/결과 통계만 있다고 사운드·경제·세이브 완료로 간주하지 않는다. 근거 없는 전체완료율·60FPS·출시일은 제시하지 않는다.

## 11. 다음 세션의 단일 작업

동일 활성 브랜치의 전체 소스 확보 → 사용 가능한 개발환경에서 고정 Godot 준비 → 소스6종/전체 파일 검사 → 네이티브7종/실제 시작 장면 → 첫 오류 수정과 같은 장면의 기본 루프 검증. 상세 실행은 NEXT_TASK를 따른다.
