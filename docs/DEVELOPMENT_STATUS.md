## 2. 문서 역할과 운영

읽기 순서는 README → AGENTS → 제작 스킬 → CURRENT_WORK → 본 문서 → PLANNED_WORK → GAME_DESIGN_BASELINE/ART_APPROVAL → NEXT_TASK다. AGENTS/스킬에 남은 과거 GAME-004B 등의 체크포인트보다 최신 CURRENT/본 문서/NEXT와 사용자 지시가 우선한다.

CURRENT는 최신 사실·본 개발현황 안내, 본 문서는 누적 이력·기능/수치·검증/미완성, PLANNED는 확정/후속/보류 계획, NEXT는 다음 연결된 기능 하나를 담당한다. 의미 있는 업데이트 뒤 세 현황 문서를 함께 갱신한다. 문서·검사·커밋 개수를 게임 완성도로 세지 않는다. 기존 BREAKERS·원조비사·검문 저장소와 승인 아트는 변경하지 않는다. 유료 Actions·외부 생성 크레딧을 자동 사용하지 않는다.

## 3. 사용자 확정사항과 임시값

모바일 가로형 서바이버 게임, 전장 주력1명, 현재 실제 캐릭터 데이터는 비야다. 레벨업 후보는 **공통 공격8 + 캐릭터 공격1 + 공통 패시브8(저항 제외) + 캐릭터 필살기 강화1 = 18종**이다. 기본적으로 서로 다른 무작위3개 중1개를 고른다. 공통16종은 공유하고 전용2종/액티브 설정은 캐릭터 데이터로 교체한다. 테스트용 fixture 캐릭터가 새 플레이 콘텐츠라는 뜻은 아니다.

전 스킬명은 **`[임시]`**다. 공격/패시브 보유 UI는 두 줄이고 고유 액티브는 별도 수동 버튼/PC F키다. 마법 자체를19번째 후보로 추가하지 않는다. 요구 경험치는 `(10+(level-1)×6)×3`, 기본 드롭은5XP다. 획득 경험치를3배 주는 규칙이 아니다. 서포터는 공격2칸·패시브2칸의 **빈 자리만** 둔다.

공격/패시브 동시 장착 각4칸, 소총Lv.1 시작, 강화상한Lv.5, 후보 동일확률, 개별 스킬 효과/계수·전장·적·마법 자원·표시 시간은 임시값이다. 후보8종을 장착8칸으로 해석하지 않는다. 원화·3D·리깅·코스튬·수집·경제·서포터 효과는 보류다.

## 6. 기능별 현재 구현

### 6.1. 기본 전투·한 판 흐름

READY/RUNNING/PAUSED/DEFEAT/CHOOSING/ABANDONED를 구분한다. 출격은 캐릭터 후보/마법 검증 후 위치·HP·통계·적/탄환/픽업/효과·성장/마법/반응을 초기화한다. 알 수 없는 캐릭터를 비야로 조용히 교체하지 않는다. 이동·경계·적 추적·최근접 자동사격·선분 탄환 충돌·관통 중복 방지·피격 무적이 연결돼 있다.

새 전투/포기는 확인창을 거친다. 확인 전 초기화하지 않고 취소는 같은 후보/ticket과 기존 상태를 보존한다. 확정 종료에만 선택을 비운다. 포기는 HP0 패배와 다른 ABANDONED이며 결과는 독립 복사본으로 고정한다. 대기에서 시간은 진행하지 않고 새 출격 전까지 결과를 유지한다. 확인 중 포커스 상실은 PAUSED 유지, 오래된 메뉴 요청은 navigation_ticket/menu_revision으로 거절한다.

### 6.3. 마법·반응·전장 표시

`viya_crimson_wave`/[임시] 진홍 파동은 버튼/F→상태/소유자/ticket/자원 검사→한 번 차감→범위 피해→기존 처치/XP→HUD 경로다. 강화0부터 사용하며 강화 선택으로 MP/쿨다운을 초기화하지 않는다. 빈 곳 발동/소비는 임시 정책이다. 이동/마법 손가락을 분리하고 정지·선택·확인·결과·대기에서는 사용과 시간을 차단한다.

반응 우선순위는 종료>피격>마법>레벨업>저체력>기본이다. 가려진 하위 반응은 시간을 보존하고 저체력 경고를 별도 유지한다. 현재 문구/테두리 대역이며 최종 표정 아트는 아니다.

CombatCues는 실제 HP 차감 뒤 숫자/치명타, 적 제거 뒤 처치 흔적, 픽업 수집/XP 부여 뒤 +XP를 기록한다. 과잉 피해 제외, 기존 치명타 판정 재사용, 드롭이나 임의 grant_xp를 수집 성공으로 표시하지 않는 기준을 유지한다. 표시 개수/수명 상한, 전투 시간 정지, 출격 초기화를 사용하며 상한 초과 시 표시만 버리고 판정/XP는 보존한다. View는 읽기 전용이며 개별 Label/Timer를 무한 생성하지 않는다.

### 6.4. 모바일 UI·상세·성장 현황

상단·전장·이동 영역·하단·모달은 공유 배치를 사용한다. 좁으면 compact, 카드는3열 또는1열 스크롤이다. 안전영역 변환과 빈 값 대체, 리사이즈 입력 해제, 후보/자원 보존을 유지한다. 실제 기기 노치·다중 터치·가독성의 별도 합격 로그는 없다.

보유 스킬 상세는 PAUSED 읽기 전용이며 닫기까지 ticket/revision을 검사한다. GAME-005에서 설정/레벨업에 성장 현황과 장착 요약을 추가했다. 공격/패시브 목록·레벨·설명, 마법 강화/profile, 실제 stats/HP를 읽으며 조회 버튼은 네 번째 선택지가 아니다.

설정에서 조회를 닫으면 설정, 선택 중 닫으면 같은 CHOOSING 후보/ticket으로 복귀한다. 앱 중단 시 PAUSED와 명시적 Continue를 유지한다. 결과/대기 조회는 종료/READY 상태를 유지한다. 두 닫기 버튼과 Esc는 같은 가드를 사용한다. 결과를 처음 열 때 최종 성장 스냅샷을 복사하고 대기에서도 보되 새 출격 시 비운다. 디스크 저장·영구 성장·보상·다음 판 계승은 아니다.

### 6.5. GAME-006 — 선택 전후 효과

기존 카드의 이름·설명·현재→다음 레벨 아래 **‘선택 시 변화’**를 추가했다. 기존 3개 후보와 확정 콜백을 그대로 쓰며 다시 그려도 재추첨하지 않는 구조다. 미리보기 helper는 보유 레벨을 복사한 뒤 순수 조회만 한다.

- 공격9종: 기본 피해와 발동 간격, 관련 발사 수·탄환당 최대 타격 대상·연쇄 대상·반경. 이전에 없던 공격은 ‘미보유’로 표시한다. 피해는 1발/1대상 기본값이며 공격력·치명타 적용 전이다. 모든 탄환이 적중한다고 가정한 총피해를 만들지 않는다.
- 패시브8종: 실제 능력치 전후 비교. 최대 체력은 최대HP와 선택 직후HP를 함께 표시한다. haste는 소총 간격을 추가로 보여주며 기존 남은 공격 대기와 고유 마법 쿨다운은 초기화하지 않는다. 경험치 획득 배율과 요구XP3배는 서로 구분한다.
- 필살기 강화: 캐릭터의 기존 MagicState.profile을 조회한다. 강화0부터 사용 가능한 마법의 첫 강화는 피해50→65·반경230→248이며 소모MP40·쿨다운12는 유지다. 현재 MP/남은 쿨다운은 그대로다. 후보 ID도 현재 캐릭터 설정과 대조한다.
- 새 공격의 Lv.0 가상 피해나 자원 충전·미리보기 선택을 만들지 않는다. 최대 레벨·슬롯 한도·알 수 없는 ID는 실제 eligible 기준을 따른다. 미리보기와 반환 Dictionary를 수정해도 실제 보유 데이터에 쓰지 않는 복사 구조다.

**실제 전투와 공유:** `_refresh_stats`와 선택 직후HP, `_auto_fire`와 `_tick_skills`가 동일 `stats_profile/selection_health/attack_profile`을 사용한다. UI에 별도 피해 공식을 복제하지 않았다. 기존 전투 값은 산술식 대조를 거쳤으며 치명타 RNG·피해 확정·타격순서·발사각·마법 소비·XP·이탈/결과는 그대로다. RunState 기존30개 함수는 원문 보존,4개 함수만 공유식 연결로 변경했다.
