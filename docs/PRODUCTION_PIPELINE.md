# VIYA — 제작 파이프라인 (제안/운영 기준)

## 소프트웨어·외주 역할
- **ChatGPT / 게임 개발 세션**: 기획 확정 사항 기록, 작업 범위 선정, Godot 코드·프로젝트, 검증·인수인계.
- **GitHub `dldlfah/Viya`**: 신규 게임의 단일 제작 기록·코드·자산 저장소. BREAKERS 본편 `main` 무변경.
- **3D 외부 제작 도구 (선택)**: Higgsfield에서 Tripo H3.1 이미지→GLB, Meshy 리깅을 호출할 수 있음. 실제 크레딧 사용/생성/다운로드는 **요청·비용·결과 확인 후**. PicLumen에서 생성한 이미지를 3D 파일이나 게임용 리그로 잘못 보고하지 않는다.
- **Godot**: 모바일 가로 전투·스킬 UI·초상화·효과 연결. 아트 처리와 게임 로직을 분리한다.

## 모델링 준비
1. ART-001 승인 얼굴·몸·의상 기준 고정.
2. 정면·측면·후면 같은 비율의 중립 포즈 원화 확보 및 실루엣 비교.
3. 3D 초안 메쉬 생성/수정 → 실제 GLB 확인 → 공통 골격/스키닝 → 장비/의상 파츠 경계 정리.
4. 타깃 기기의 화면 크기·FPS와 이동·사격 애니메이션 검수.
5. 인게임이 2D이면 동일 모델로 방향별 스프라이트 렌더·투명도·프레임/상태 표준 확정.

## 최소 개발 단위
- 첫 단위는 **모바일 가로 시작 화면 + 주력 플레이어 이동·카메라·터치 입력 + 적 추적·자동사격·HP**. 이미지 미완성이어도 플레이 가능해야 한다.
- 그 다음 경험치·레벨업, 스킬 2줄·환경설정/필살기, 초상화 반응, 서포터 빈 슬롯 순으로 확장한다.
- 콘텐츠 설계 확장은 초기에 보류한다. 10종 캐릭터/수십 장 코스튬/경제·뽑기는 첫 동작 확인 후.
- 새 시안 제작이 기존 UI/게임플레이 연결보다 앞서 무한히 반복되면 우선순위 재평가.

## 보존과 QA
- 정적 시안·기하/리깅 자체 검증·Godot 실행·모바일 실기·프로듀서 품질 승인을 개별 상태로 관리.
- 코드 SHA와 동일한 버전의 검사만 PASS로 기록하고 모바일 미실행이면 NOT_VERIFIED.
- 필요 없는 전체 회귀·유료 Actions 실행·원본 덮어쓰기 금지.
