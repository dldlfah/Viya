# VIYA — 다음 단일 게임 작업

## GAME-002: 경험치 → 18종 후보에서 무작위 3선택 → 공격/패시브 표시와 강화 연결

먼저 [통합 작업 예정 문서](PLANNED_WORK.md)의 **2.1절 확정 구성과 2.2절 구현 기준**, [현재 상태](CURRENT_WORK.md)를 읽는다. **비야 원화·모델링은 보류이며 이 작업으로 자동 복귀하지 않는다.** 레벨업 규칙의 단일 기준은 PLANNED_WORK이며 별도 기획서를 늘리지 않는다.

같은 작업 브랜치의 GAME-001 코드를 이어 사용한다. 적 처치에서 경험치가 생성되고 플레이어가 획득하면 레벨업 선택창이 열리도록 연결한다.

### 이번 구현 범위
- 후보 구성: 모든 클래스 공통 공격 8종 + 출격 캐릭터 전용 1종 + 공통 패시브 8종(저항력 제외) + 출격 캐릭터 고유 필살기 강화 1종 = **18종**.
- 레벨업마다 기본 **서로 다른 후보 3개를 무작위 제시 → 1개 선택**. 각 분류 1개씩 강제 배분하지 않는다.
- 공통 후보와 캐릭터별 전용 후보를 데이터에서 구분한다. 비야로 출격하면 비야 전용 후보를 사용하고, 다른 캐릭터 ID로 출격할 때 전용 스킬과 필살기 강화 후보를 해당 캐릭터 것으로 교체하는 구조다. 새 캐릭터 콘텐츠·수집 기능 제작은 범위 밖이다.
- 신규 획득/기존 스킬 강화를 구분하고 선택한 효과와 보유 레벨을 실제 상태 및 두 줄 HUD에 연결한다. 필살기 강화 상태는 GAME-003 고유 마법의 발동/효과와 연결할 수 있게 분리한다. 발동이 미구현이면 강화 데이터 저장만으로 실제 마법 적용 완료를 주장하지 않는다.
- 후보 **종류 수 8종과 동시 장착 8칸은 다른 개념**이다. 기존 공격/패시브 4칸은 임시 UI이며 이번 지시만으로 장착 한도를 바꾸지 않는다.
- 개별 스킬 이름·효과·수치·강화 상한·추첨 가중치는 아직 확정되지 않았다. 필요한 시제품 값은 임시로 표시하고 사용자 확정사항과 구분한다. 유효 후보 3개 미만의 예외는 중복 후보·새 정규 스킬을 임의 추가하지 않는 방식으로 별도 명시한다.

### 완료 조건
- 실제 전투에서 처치 → 경험치 획득 → 선택창 → 효과 반영 → 전투 복귀가 연결된다.
- 공통/전용 후보 합계와 패시브 저항 제외가 검증되고, 현재 캐릭터와 다른 전용 스킬이 제시되지 않는다.
- 한 선택창에 같은 스킬이 반복되지 않으며, 선택 1회당 적용은 1회다. 캐릭터 변경/재시작 시 이전 선택·강화·후보 상태를 초기화한다.
- 선택 중 전투/투사체/피격 타이머가 멈추며, 다중 레벨업·중복 터치·환경설정·사망·재시작과 충돌하지 않는다.
- 현재 적/탄환 상한, 이동 터치 소유권, 재시작 초기화를 보존한다. 서포터는 빈 자리만 유지하며 수집·버프·과금은 구현하지 않는다.
- 엔진이 사용 가능하면 먼저 GAME-001의 실제 import/엔진 테스트를 실행해 **발견된 실제 오류를 우선 수정**한 뒤 새 기능을 검증한다. 엔진이 여전히 없으면 미검증을 유지하고 가능한 구현을 진행한다; 매회 사용자 PC 로그 요청이나 서류 검수로 작업을 중단하지 않는다.
- 코드 작성과 Godot 실행 PASS, 모바일 실기 PASS를 구분한다. 최종 실행 미검증은 숨기지 않는다.

이후 마법 연결은 `PLANNED_WORK.md`의 GAME-003 순서를 따른다. 보류 아트 작업에는 별도 재개 지시가 필요하다.
