## GAME-004C: 전투 이탈 확인과 결과 → 출격 대기 복귀

[PLANNED_WORK.md](PLANNED_WORK.md)의 GAME-004 한 판 흐름과 CURRENT_WORK·DEVELOPMENT_STATUS를 기준으로 이어간다. 비야 아트는 보류 유지. 기존 HUD 코드는 작성/정적 검사까지만 완료했고 엔진·기기 미검증이다. **이번 기록 요청 뒤에도 다음 게임 작업은 GAME-004C 그대로다.**

1. 현재 `scenes/main.tscn`은 기존 main을 상속하는 `scripts/ui/mobile_main.gd`를 사용한다. 새 UI를 버리거나 원래 고정 HUD로 되돌리지 않는다. 엔진 사용이 가능해지면 기존 전체 검사에서 첫 실제 오류를 우선 수정한다.
2. 전투/레벨업 선택 중 실수로 새 전투를 시작해 성장 상태가 사라지지 않도록, 이탈·새 전투 시작에는 확인 단계를 둔다. 취소는 기존 전투 또는 같은 후보/ticket으로 돌아가고, 확인 전에는 HP·MP·성장·통계가 초기화되지 않아야 한다.
3. 결과 화면에서 재출격뿐 아니라 출격 대기 화면으로 돌아오는 경로를 연결한다. 전투 중 이탈과 실제 HP 소진에 의한 패배를 구분하고, 보상·경제·새 승리 조건은 추가하지 않는다.
4. 확인/취소·결과·대기 화면 중 이동·마법·피드백 시간 정지, 재시작·포커스 상실·중복 콜백 처리를 검증한다. 현재 responsive HUD/상세창과 안전영역을 재사용한다.
5. 스킬18종/3선택·임시 명칭·요구 XP3배·마법/반응 상태·서포터 빈칸을 보존한다. 코드·정적 검사·엔진·실기 결과를 구분하고 사용자에게 반복 Pull/로그 제출을 요구하지 않는다.

완료 기준은 확인/취소 → 기존 상태 보존 또는 명시적 종료 → 결과 → 대기/재출격이 같은 게임 상태 소유자에서 연결되는 것이다. 새로운 대규모 기획 문서나 캐릭터 아트로 범위를 전환하지 않는다.

작업 후 CURRENT_WORK, DEVELOPMENT_STATUS의 최신 현황·누적 이력·검증 근거, NEXT_TASK를 함께 갱신한다. 향후 계획 변경은 PLANNED_WORK에서 관리하고 이 문서와 중복 확정하지 않는다. `main` 자동 병합은 하지 않는다.
