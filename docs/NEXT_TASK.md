### 이번 재개에서 해야 할 일

1. 동일 브랜치의 **전체 프로젝트**를 개발 실행환경에 확보한다. 이전 부분 회수 디렉터리를 전체 저장소로 오인하지 않는다. main은 아직 게임 코드가 없는 이전 기획본이며 새 프로젝트로 재작성하지 않는다.
2. Linux x86_64 개발 에이전트에서는 `python tools/bootstrap_godot.py --check`로 고정 Godot 준비와 기존 전체 검사를 실행할 수 있도록 코드가 마련되어 있다. 오프라인 공식 ZIP이 준비된 환경은 `--archive /verified/path/Godot_v4.7.2-stable_linux.x86_64.zip`를 지정한다. 이미 준비된 다른 운영체제 실행환경은 `python tools/check_project.py --godot /actual/path/to/Godot`를 사용한다. 이는 **개발 에이전트의 작업 지침**이지 사용자에게 파일 설치·수동 패치를 요구하는 안내가 아니다.
3. 다운로드 실패/엔진 미확보와 게임 결함을 구분한다. bootstrap의 종료0은 엔진 준비일 뿐 게임 합격이 아니며, 종료2는 환경 미준비다. 현재 기록은 DNS 실패로 준비 미완료다. 계정 환경을 실제 생성하는 수단이 없으면 생성했다고 보고하지 않는다.
4. 전체 소스·데이터 검사6종 → import/구문·타입 → 기존 전투·성장·마법·반응·HUD·내비게이션·전장 피드백 Godot 시험 → 실제 시작 장면 순서로 첫 결함을 수정한다. 기존 시험·assertions·실패 판정을 삭제/완화하지 않는다.
5. 시작 장면 `project.godot → scenes/main.tscn → mobile_main.gd → main.gd/RunState`를 유지한다. 출격→이동/사격→처치/XP→3선택→마법→상태/전장표시→이탈 취소/확정 또는 패배→결과→대기/재출격을 같은 장면에서 검증한다.
6. 새 상세창 닫기 가드의 낡은 Callable, 같은 후보/ticket 유지, 앱 중단, 재시작, 시뮬레이션 시간/자원 정지, 표시 상한과 RNG 분리를 회귀 대상으로 삼는다. 화면 확보가 가능하면 가로 기본/좁은/넓은 배치와 실제 입력을 점검한다. 물리 모바일·FPS는 별도 검증한다.
