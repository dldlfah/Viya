# VIYA — 다음 단일 게임 작업

## GAME-004B: 모바일 가로 HUD 배치와 조작 영역 연결 보완

먼저 [PLANNED_WORK.md](PLANNED_WORK.md), [CURRENT_WORK.md](CURRENT_WORK.md)를 읽는다. GAME-004의 반응 상태·결과 표시 코드는 연결했으나 실제 엔진·렌더·모바일 실행은 미검증이다. 기존 아트 제작은 보류한다.

1. 같은 작업 브랜치의 현재 전투/성장/마법/반응 코드를 재사용한다. 실행 가능한 Godot가 있으면 먼저 기존 기반·성장·마법·반응 테스트를 실제 실행하고 첫 구문/타입/동작 오류를 수정한다. 검사를 느슨하게 만들거나 사용자에게 매번 Pull/로그를 요구하지 않는다.
2. 1280×720 기준으로 하드코딩된 상단/하단·전장·이동 터치 영역을 한 배치 기준으로 묶는다. 화면 비율/크기가 바뀔 때 반응 영역·HP/MP·공격/패시브 두 줄·서포터 빈칸·마법 버튼이 겹치지 않게 한다.
3. 작은 화면의 긴 `[임시]` 스킬명과 레벨업 카드 설명을 처리한다. 잘린 이름은 터치로 확인 가능한 세부 표시를 제공하되 카드의 중복 선택·즉시 발동을 만들지 않는다.
4. HUD 실제 영역을 이동/마법 입력 판정에 반영하고 손가락 소유권, 선택·설정·포커스 상실 시 해제 및 재개를 보존한다. 입력을 막는 장식 컨트롤과 모달 상태를 구분한다.
5. 기준 화면과 더 넓은 가로 화면에서 실제 레이아웃/입력 검사를 작성한다. 실행이 불가능하면 코드·정적 검사와 기기 미검증을 구분한다. 임의의 60 FPS/최소 사양 합격이나 목표 기기 완료를 보고하지 않는다.

완료 조건: 동일 상태 소유자를 유지하면서 표시·터치 영역의 배치 기준을 연결하고, 크기 변경·모달·재시작에도 조작 경로가 유지되는 코드와 검증 근거를 남긴다. 스킬 후보18/3선택·요구 XP3배·임시 명칭·마법 자원·반응 우선순위·빈 서포터2+2를 보존한다. 새 캐릭터·원화·3D·수집·지원 버프·과금으로 확대하지 않는다.
