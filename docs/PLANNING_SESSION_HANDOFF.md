## 7. 매번 갱신할 내용과 완료 보고

사용자 결정·작업 범위 변경, 외부 제출/상태 변경, 생성 결과의 채택/탈락, 아트 납품·게임 인계, 검증 결과, 챕터 상태가 바뀌면 **작업 턴 안에서 이 문서의 현재 요약을 갱신**한다. 세션 끝에만 몰아서 기록하지 않는다. 단순 대화로 상태가 바뀌지 않았으면 불필요한 새 이력을 만들지 않는다.

다음 세션이 알아야 할 최소 항목은 **갱신일/확인한 원격 기준, 챕터/완료 수, 마지막 완료 알림, 확정/추천/미결정, 작업 중 파일/담당, 외부 작업ID/상태·비용, 납품/연결/실행/승인 상태와 근거 경로, 남은 조건, 다음 한 작업**이다. 세션 전환 때 미커밋 변경이 있으면 소유/범위와 재개 위치를 남기고 다른 세션 작업을 버리지 않는다.

PLANNED_WORK96절의 진행표, CURRENT의 최신 사실, NEXT의 다음 작업과 이 문서의 현재 표를 맞추고 상세 누적 이력은 DEVELOPMENT_STATUS에 추가한다. 자산이 바뀌면 ASSET_MANIFEST도 갱신한다. 새 채팅별 복사 문서나 독립 진행표를 늘리지 않는다. 완료 챕터/알림은 실제 수행한 범위만 기록한다.

각 챕터의 실제 기준을 충족한 턴에서 **“플랜B B-XX 완료 — 확인 근거 / 남은 한계 / 다음 B-YY”**를 사용자에게 알리고 마지막 알림 항목을 갱신한다. 여러 챕터는 각각 보고하며 부분 완료와 구분한다. 채팅 밖 자동 개발/예약 알림을 약속하지 않는다.

기존 작업 브랜치에서 사용자/다른 세션 변경과 실제 원격 HEAD를 재확인하고 의미 단위로 보존한다. 문서 커밋과 실제 게임/아트 커밋을 구분하고 main 자동 병합·force push·유료 Actions를 하지 않는다.
