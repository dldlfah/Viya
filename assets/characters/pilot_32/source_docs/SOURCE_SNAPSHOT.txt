피격 발생·방향·시계
새 received cue 또는 HP 감소에서 hurt_until=now+0.12가 된다. pose 우선순위는 hurt > attack > run > idle다. hurt로 새로 진입할 때 since=now이며, 같은 hurt 중 다시 맞으면 종료 시각은 연장해도 since는 다시 시작하지 않는다. 따라서 비반복6프레임이 끝나도 피격 pose가 유지되는 동안 마지막 프레임에 머물 수 있다.

각 새 cue에서 hurt_aim을 먼저 지우고 direction이 0이 아닐 때만 새 값을 넣는다. 마지막 cue의 방향이 우선하며, 마지막 cue 방향이 0이면 앞 cue의 방향을 남기지 않는다. 새 cue 없이 HP만 줄어도 오래된 hurt_aim을 제거한다. hurt_aim이 없으면 이동 중 displacement, 정지 중 전달 facing을 따른다. 이 방향을 최종 표시 단계에서 투영·양자화한다. 피격 판정·HP·무적·cue는 게임이 소유하며 이미지가 추가 피해나 새 규칙을 만들지 않는다.

납품 hurt_ne는6장×20ms=120ms, 각 duration1·FPS50·loop=false다. native GIF의 컨테이너 반복과 게임 SpriteFrames 비반복은 별개다. 고각 _draw_hero()의 텍스처 분기는 draw_texture_rect(...,false)로 그리며, 절차형 Forms.hero에 전달하는 hurt_clock>.5를 PNG에 자동 전달하지 않는다. 이번 그림에 피격 플래시·피·총구 효과를 굽거나 같은 깜박임이 자동 구현됐다고 보고하지 않는다. 기존 피해 cue/표시와 자산 반응을 실제 연결 단계에서 구분한다.

NE 투영·표시·슬롯
NE는 e,se,s,sw,w,nw,n,ne 중 인덱스7, 투영된 화면 오른쪽 위 섹터다. 사선 siege_battlefield는 high_angle && oblique_enabled일 때 facing을 project_direction()으로 투영한 뒤8방향으로 다시 양자화한다. 고정 yaw −18도·지면 앙각55도에서 월드(1,-1)는 양의 zoom×(0.6420395219202062,-1.0321917922198198), 각도−58.117738386614도로 ne다. 정확한 화면−45도와 같은 월드축은 아니다. 계산은 코드 산술이며 게임 측정이 아니다.

배우의 발 위치만 투영하고 IDENTITY 캔버스에서50×62, pivot(0.5,1)로 직립 표시한다. PNG 자체 회전·지면 Y압축·zoom·자동 좌우 반전은 없다. 원본400×496에서 공통200×248 RGBA/sRGB로 준비했다. 실측 공통 crop[103,7,324,467], 배율0.5304347826086957, 크기117×244, offset[41,4]를 전 프레임에 동일 적용했다. viya_battle은 빈 공용 슬롯이다. 조회 순서는 동작_방향 → 방향 없는 동작 → idle_방향 → idle → default다. 이번 누적 자산에 공통 idle/default와 방향 없는 동작은 넣지 않는다.

직접 참조와 완료한 파일 구성
직접 생성 참조는 PILOT-029 NE 대기 job b46f2d0f-4a9e-4f3a-b656-577bba46cf60 하나다. PILOT-030 run_ne, PILOT-031 attack_ne와 ART-001은 이번 직접 입력이 아니다. 기준은 NE 후면3/4의 기존 의상과 두 손 장비다. 피격은 짧은 몸 수축·회복 후보이며 실제6장을 직접 확인했다.
