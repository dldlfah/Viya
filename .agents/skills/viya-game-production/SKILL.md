# Viya Game Production — 제작 운영 스킬 v1.1

## 최신 우선순위

**단일 작업 예정 문서: `docs/PLANNED_WORK.md`.** 비야는 ART-001 시안 확정 단계에서 일단 마무리한다. 원화 정합화·3D·리그·코스튬은 보류다. 게임 기본 루프를 먼저 구현하며 `다음`은 게임 기능을 계속한다. 과거 P0/P0-B 캐릭터 선행 계획은 자동 재개하지 않는다. 이 변경은 프로듀서의 2026-11-17 최신 지시에 근거한다.

## 사용 조건과 시작

`dldlfah/Viya` 신규 모바일 가로 게임 전용이다. 기존 BREAKERS 본편이나 원작 복원에는 자동 적용하지 않는다. 복원용 스킬에서 진행관리/종료조건/검증/비용통제만 재사용하며 DOS 동등성·원본 주소/RNG 같은 복원 규칙은 전파하지 않는다.

README → AGENTS → PLANNED_WORK → GAME_DESIGN_BASELINE → ART_APPROVAL → CURRENT_WORK → NEXT_TASK를 읽는다. 실제 브랜치/HEAD/변경 파일/검증 환경을 확인하며 없는 파일·도구·커밋·실행을 있다고 주장하지 않는다. 최신 사용자 지시와 충돌하는 과거 지침은 대체 관계를 기록한다.

## 매 `다음`

1. NEXT의 연결된 게임 기능 한 묶음을 구현한다. 입력 → 상태 변경 → 화면/효과/결과 → 다음 행동까지 연결하며 이미 있는 코드를 재사용한다. 작은 수정·검수 문서만 반복하지 않는다.
2. 게임 상태 소유자, 입력, 화면 표현을 분리한다. 임시 도형으로 플레이를 먼저 연결하고 원화 미완성을 게임 제작 중단 이유로 삼지 않는다.
3. 변경 범위에 맞춰 리소스·구문·입력·상태·실행을 검증한다. 실행 불가 환경은 NOT_VERIFIED. 실제 오류가 확인되면 해당 오류가 우선이며 미실행을 실패로 단정하지 않는다.
4. 기존 활성 작업 브랜치에서 권한 범위 내 의미 단위로 원격 보존한다. HEAD/미커밋/동시 변경 확인, force push·main 자동 병합·유료 Actions 금지.
5. CURRENT는 현재 사실, NEXT는 다음 게임 작업 하나로 갱신한다. 후속/보류 계획은 PLANNED_WORK에만 통합하고 작업문서에 그 존재를 유지한다.
6. 실제 구현, 검증 범위와 버전, 미검증/미완성, 다음 한 작업만 보고한다. 매회 사용자 Pull·로그를 요구하거나 채팅 밖 자동 작업을 약속하지 않는다.

## 보호할 기준

기존 BREAKERS/REALWONJO/TRIGATE 및 승인 시안 불변. 비야의 성숙한 얼굴·체형·의상·노출 구조·화풍을 임의 재설계하지 않는다. R1/R2와 SAM GLB는 최종 비야로 사용하지 않는다. 게임은 모바일 가로, 주력1명, 향후 서포터2+2 빈칸, 공격/패시브 두 줄, 고유 마법 터치, 반응 초상화, 환경설정 방향을 유지한다. 수집·뽑기·과금·다수 캐릭터·서포터 수치를 미리 만들지 않는다.

## 보류 아트 재개 조건

프로듀서가 재개를 지시한 경우 PLANNED_WORK의 Higgsfield 부분 편집 계획을 따른다. 승인 시안과 수정 대상을 분리하고 모델/마스크/설정/비용을 재조회한다. 한 부위부터 검증하며 수정 범위 밖은 원본 보존 및 전후 비교로 확인한다. 도구 기능 보유를 원화 일치 보장으로 해석하지 않는다. 사용자 승인 없는 도구 교체·전체 재생성 금지. 캐릭터 3D/2D 표현은 향후 품질/기기 실측 후 결정한다.

## 완료 상태

PASS는 해당 소스에서 실제 확인한 범위만, FAIL은 재현 결함, NOT_VERIFIED는 미실행/미확인, BLOCKED는 필수 자산·접근 부재로 구분한다. 기본 파일 검사나 생성 완료를 엔진/모바일/아트 합격으로 확대하지 않는다. 코드가 작성돼 있어도 실행을 확인하지 못하면 `코드 작성·연결 / 실제 실행 미검증`으로 남긴다.
