# Viya Game Production — 신규 게임 제작 운영 스킬 v1.0

## 사용 조건
- 적용 프로젝트: `dldlfah/Viya` 신규 모바일 가로형 서바이버 게임. `BREAKERS` 본편을 개조하는 요청에는 자동 적용하지 않는다.
- 이 스킬은 이전 `game-restoration-finishline`의 **진행관리/완료조건/검증/비용 통제 방식만 재사용**한 신규 프로젝트 전용 파생 운영 스킬이다.
- 이전 스킬의 원작 파일·증거·DOS 동등성·복원 단계·주소/RNG 준수·종료 요건은 여기에 적용하지 않는다.

## 매 세션 시작
1. GitHub 저장소의 `AGENTS.md`, `docs/GAME_DESIGN_BASELINE.md`, `docs/ART_APPROVAL.md`, `docs/CURRENT_WORK.md`, `docs/NEXT_TASK.md`를 읽는다.
2. 실제 리포지토리 브랜치/HEAD·변경·검증 가능 환경을 확인한다. 기록에만 있는 파일/실행을 있다고 가정하지 않는다.
3. 프로듀서 최신 지시와 확정된 범위를 비교한다. 새 지시가 이전 사항을 대체하면 범위와 이유를 기록.
4. 각 작업은 **실제로 플레이 가능한 기능 묶음**을 우선: 입력 → 게임 상태 변경 → 화면·효과·결과 → 다음 행동.

## 반드시 지킬 보호 규칙
- 기존 BREAKERS, REALWONJO, TRIGATE 코드/원화/저장소 수정 없이 신규 게임을 독립적으로 구축.
- 비야 승인 디자인의 성숙한 얼굴·체형·의상 노출 구도·색상·유니크한 화풍을 임의로 재설계하지 않는다.
- 새 시안/모델링용 레퍼런스를 승인된 원화 자체로 덮어쓰지 않는다. 시안, 실제 메시, 스켈레톤, 코스튬 교체 완성의 상태를 분리한다.
- 게임 장르/플랫폼: 모바일 가로 뱀서류, 1명의 주력과 향후 서포터. **서포터 슬롯은 먼저 마련, 능력·수집·수치 시스템은 아직 만들지 않는다.**
- 스킬 HUD 두 줄(공격·패시브), 터치형 고유 마법 필살기, 상태 반응형 라이브 초상화, 환경설정 공간을 보호한다.
- 사용자 승인 없이 과도한 스토리/뽑기/과금/희귀도/스킬 수치를 잠그지 않는다.

## 한 번의 '다음' 수행
1. `NEXT_TASK.md`에 적힌 **단 하나의 기능 묶음**을 확인한다. 작은 수정이 여러 개 분산되면 기능 완성 단위로 묶는다.
2. 이미 있는 구현과 리소스를 재사용하고 새로운 코드가 기존 로직과 실제 연결되도록 한다.
3. Godot 구문/입력/상태 전환/화면 연동 테스트를 수정 범위에 맞게 수행. 모바일 실기 불가능하면 NOT_VERIFIED.
4. 시각 결과는 승인 비야 원화와 같은 화면 크기에서 비교하고 캐릭터 정체성/전투 가독성/성능을 확인.
5. 현재 브랜치에 실제 의미 있는 구현을 원격 보존하는 것은 프로젝트의 게시 권한과 충돌이 없는 범위에서만. 원격 HEAD 확인, force push 금지, 유료 Actions 무단 실행 금지.
6. `docs/CURRENT_WORK.md`를 현재 사실로 갱신하고 `docs/NEXT_TASK.md`는 다음 단일 작업으로 교체한다.
7. 결과를 짧게 보고: 실제 구현·검증 결과(환경/커밋)·미검증 범위·다음 하나의 기능.

## 외부 3D/아트 파이프라인
- 비야 승인 아트와 새 생성 결과의 목적(컨셉/모델링 기준/실제 GLB/리그/2D 렌더)을 명시.
- Tripo/Meshy/Higgsfield 등 외부 모델의 지원 기능·금액·입력·출력을 **실제 조회**. 비용 집행 전 사용자 지정 조건·의사 확인.
- 처음부터 커스텀 의상 전품목을 만들지 않는다. 공통 신체·골격, 이후 교체 가능한 의상 메쉬 구조를 목표로만 설정.
- 3D/2D 인게임 표현 방식은 기기·품질 검증 후 잠근다. 추측으로 최종 모델링 완성/60 FPS를 보고하지 않는다.

## 완료 판단
- `PASS`: 지정 SHA에서 실제 성공 로그/캡처 등 증거 확보.
- `FAIL`: 재현된 결함. 원인과 재현 입력 기록.
- `NOT_VERIFIED`: 실행을 아직 하지 못한 환경/아트 퀄리티/플랫폼.
- `BLOCKED`: 자산 또는 접근·필수 선행조건 부재로 해당 기능 구현 불가.
- 단일 테스트 통과를 전체 전투, 모바일 성능, 아트 최종 승인으로 확장하지 않는다.
- 실기 검수 대기와 실제 실패는 분리한다.

## 첫 작업 목표
모바일 가로 Godot 프로젝트 생성 → 임시 비야 표시/이동 → 적 추적·기본 자동사격·HP·적 제거 → 실제 동작을 확인하는 첫 전투 루프. 추가 스킬·UI·모델링·서포터 정식 기능은 순차 연결.
