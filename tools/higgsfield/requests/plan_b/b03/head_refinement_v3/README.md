## 실제 편집

입력은 `../head_refinement_v2/viya_head_contours.blend`(SHA `178ed27e112016fa86a6398944bbd922f310a3f381379b497beb7020ce46cb6d`)다. 현재 후속 파일은 `viya_head_rims.blend`다. 원래 기본형/모든 제어 좌표·값/상대 기준, UV/토폴로지/원본 정점 인덱스를 유지하고 피부에 두 제어 `R3_LidRim`, `R3_MouthCorner`를 추가했다. 새 머리/리그·이전 폐기 생성물은 불러오지 않았다.

양쪽 눈에서 독립적으로 실제 닫힌28정점 면 고리를 확인했다. `loop_selection.json`은 관찰/선택한 원본 정점 인덱스와 고리 사이 연결 관계다. 인접한 고리마다 정확히 하나의 대응 정점/일대일 대응을 검증했다. 좌우 좌표를 반전해 복사한 것이 아니다. JSON의 eye_left/right는 정면 화면 기준 작업X 음수/양수 구분이며 원본 helper-l/r의 해부학 명칭과 같다고 가정하지 않는다.

눈 개구 고리56정점과 눈알 두 개는 고정했다. 앞뒤 테두리 고리를 고정된 개구 쪽으로50% 이동하고, 바깥 전이 고리는24%/10%/3%로 완화했다. 50%는 기존 고리 사이의 작업 좌표 거리 비율이며 원화에서 얻은3D 치수나 닮음 점수가 아니다. 고리 측정과 실제 정점별 전후 좌표는 `build_result.json`/`feature_samples.csv`에 남겼다.

입은 실제 닫힌38정점 고리7개에서 X 양끝을 기준으로 위/아래 경로를 나눴다. 반대쪽 경로의 대응 위치로 기존 입선 중심을 계산하고 안쪽 벌어짐을 줄였다. 입꼬리 최대0.35mm의 국소 올림을 더해 경한 아래 꺾임을 완화했다. 고리마다2~32%의 수축을 사용하며 입 전체를 가짜 정지 평면/새 곡면으로 바꾸지 않았다. 현재 코0.55와 기존 눈·턱 제어는 그대로다.

## 단계 판단과 남은 범위

정면·양측면·양 사선/55도 무채색을 직접 비교했다. 눈의 전체 개구/간격과 코·턱 비례를 유지하면서 테두리가 가늘어지고 입선의 벌어짐/입꼬리 꺾임이 완화됐다. 검수 이미지에서 새 큰 틈/돌출·입선 단절은 보이지 않았다. 이에 **기획·아트가 기본형을04 UV/색 작업에 사용할 단계로 자체 수용**했다. 파일/숫자 검사만으로 원화 일치를 판정한 것은 아니다.

눈썹·홍채·얼굴색/그림의 눈·입선, 머리카락이 없어 완성 얼굴 인상은 아직 판단할 수 없다. 가려진 헤어라인/귀·뒤 두상은 이전 임시 가정을 유지한다. 원본4장은 정합된 같은 투영 도면이 아니며 원본px 길이를3D 맞춤값으로 쓰지 않는다. 55도는 머리만 진단한 것이고 실제 게임 표시 크기/전신·실기를 검증한 것은 아니다.

**다음04는 현재 형태/제어를 보존한 얼굴UV/색·선 작업**이다. 먼저 UV checker/면 고리·이음선/늘어짐을 확인하고 기존 원본4장의 역할에 맞게 얼굴 색과 눈/눈썹·입선을 배치한다. 원본 정면을 얼굴 인상 주 기준안으로 사용하며 측면은 깊이/시점 대조다. 정면 이미지를 얼굴 전체에 단순 평면 투영해 측면을 뭉개는 방식으로 끝내지 않는다. 얼굴 원본의 실제 해상도를 기록하고 자동 업스케일/새 유료 생성은 하지 않는다. 새 색/선이 형상 결함을 드러내면03으로 돌아가 해당 부위와 시점을 다시 확인한다. 얼굴 수용 전 몸/총기·리그로 넘어가지 않는다.
