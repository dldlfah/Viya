## 직접 확인한 차이

| 항목 | 판단 | 근거와 적용 범위 |
| --- | --- | --- |
| 화면 왼쪽 홍채의 밝은 세부 누락 | **전사 입력 누락 확인** | 기존13×13 원천영역은(727,182) 중심이다. 보이는 밝은 표본(737,178), RGB(211,197,200)이 그 범위 밖이다. 기존 `eye_texture()`의 가로/세로 반경5.5px 샘플링으로 포함할 수 없다. 원래 맵을 정확히 보존한 것만으로 이 누락이 해결되지 않는다. |
| 눈/눈썹·입의 전체 표정 | 아트 자체 검수 미통과 | 현재 정면은 원화의 성숙한 눈매/표정과 충분히 맞지 않는다. 미보정 원화의 기울기·머리카락 가림도 영향을 주므로 특정 눈꺼풀/눈썹3D 수치를 새로 확정하지 않는다. |
| 입술/턱의 둥근 인상 | 아트 자체 검수 미통과·국소 형상 검토 후보 | 정면과 양측면에서 원화보다 둥글고 부드럽게 읽히며 무채색에서도 윤곽이 남는다. 양측 원화도 서로 달라 길이/돌출의 정확한mm와 새 키 값은 미확정이다. |
| 작은 표시에서 정체성 | 실제 게임 미검증 | 머리만 축소하면 세부가 거의 읽히지 않는다. 이를 원화 차이를 무시하거나 게임 가독성을 통과시킬 근거로 쓰지 않는다. |

홍채 기준점은 처음에 수동2D 관찰 오차±4px로 기록된 값이다. 이를 작은 영역의 확정된 중심/정확한 범위로 사용한 것이 누락 경로다. 확인한 것은 **특정 밝은 원천 세부가 제외된 사실**이며 모든 얼굴 인상 차이/과거 생성 모델 왜곡의 단일 원인을 입증한 것은 아니다. 가려진 홍채·동공의 실제 중심과 전체 형상은 복구하지 않았다.

머리카락은06 단계의 후속 제작이다. 현재 가림 미제작은 비교의 한계로 남기되, **머리카락이 없다는 이유만으로05를 영구 차단하거나06으로 먼저 넘어가지 않는다.** 이번 미통과의 근거는 위의 가시 얼굴 차이/확인된 전사 누락이다. 원화 정면을 주 얼굴 기준으로 하고 양측면은 윤곽/깊이 대조, 후면은 얼굴 판정에서 제외했다. 정합 도면으로 간주하거나 좌우 반전·원본 변형을 하지 않았다.

## 표시 추정의 범위

작업신장1.72m와 기존 표시높이85.56px를 비교 가정으로 사용했다. 기존 검수 렌더512×640/정사영 높이0.335m에서 같은 길이당 픽셀 비율로 줄이면 전체 머리 뷰포트는 반올림13×17px다.69×86 빈 카드에 머리만 배치하고1배/4배 최근접 확대를 함께 보였다. 실제 몸·생산 카메라/셰이더·GPU 래스터·S20+ 화면을 재현한 것이 아니다. 상세 수식/반올림과 좌표는 `comparison_registration.json`에 있다.

## 다음 한 작업

**B-03-04: 현재 모델/UV에서 홍채 전사 범위와 등록만 보완한다.** `../eye_surface_v1/viya_eye_surface.blend`를 입력으로 하고 파생물은 `../eye_surface_v2/`에 둔다. 양쪽의 보이는 홍채·동공/하단색·반사 범위를 별도로 직접 확인하고, 기존 수동 중심을 확정값으로 복사하지 않는다. 원본4장·형상/모든 키·R5/R4·코0.55·양UV·머리색/흰자 보완은 보존한다. 현재 홍채 맵은 입력 이력으로 보존하되 누락된 등록 자체를 보호 대상으로 고정하지 않는다.

더 넓은 직사각형의 피부/흰자·속눈썹까지 눈알에 통째로 붙이지 않는다. 필요한 가시 영역을 분리하고 가려진 부분의 작성 가정/실제 원천색을 구분한다. 반대 눈 복사·원본 반전·AI 복원/새 원화 생성은 하지 않는다. 현재 맵/입력은 덮어쓰지 않고 정면/양 사선·무조명/재개방으로 확인한다. 원래 홍채색·눈알/개구 형상을 바꾸거나 눈/눈썹을 다시 광역 보정하는 것으로 해결하지 않는다.

전사 보완 뒤에도 남는 입술/턱 차이는03의 해당 국소 영향 검수로만 돌아갈 후보로 기록했다. 이번에 새 턱 수치나 전체 머리 재생성·모든 얼굴의 재작업을 지시하지 않았다.05 수용 전 몸/총기·리그/게임 적용으로 넘기지 않는다.

## 실행·보존 근거

`render_review.py`가 현재 `viya_eye_surface.blend`를 새 Blender 프로세스에서 열어 기존 검수 카메라/재질로 색6시점, 임시 동일 회색 재질로 정면/양측면·사선4시점을 실제 렌더했다. Blender4.3.2/Cycles32샘플·기존512×640/정사영0.335m를 유지했다. 재질/카메라를 메모리에서 복원해 형상/모든 키·평가 제어 좌표/양UV·활성 이미지와 입력 파일 해시 불변을 확인했고 **모델은 저장하지 않았다**.

색6시점의 새 렌더는 이전 패킷 같은 시점과 디코딩RGBA가 동일했다. 이는 현재 비교의 재현/보존 근거이며 전체 접촉·자기 교차/변형·얼굴 닮음·최종Godot 셰이더/게임 승인이 아니다. 원본4장의 크기/해시·입력SHA `97b8a658207b0f27af355c32c37bfd645f57addaa8230770e657bdb92c4b6c05`도 불변이다. 기존 게임 자산/코드·임시3D·전투/저장 규칙을 변경하지 않았다.
